# 第 1 课：先认识“共同语言”和纯逻辑

这一课探索两个最底层的包：`robogame_interfaces` 定义各模块交换的数据格式，`robogame_core` 保存不依赖 ROS2 节点的算法和业务规则。先理解它们，后续看感知、定位和控制时就知道数据从哪里来、要去哪里。

## 实验 A：接口是合同

程序会直接读取三个真实接口文件：

- `CubeDetection.msg`：感知模块如何描述一个方块，包括颜色、置信度、距离和像素位置。
- `CargoState.msg`：机器人如何报告已装载的橙色、紫色和总数量。
- `ExecuteMechanism.srv`：调用机构时发什么请求，又会收到什么结果；`---` 上面是请求，下面是响应。

本实验不编译消息，因为第一步只需认识接口。`.msg` 和 `.srv` 不是算法，它们是模块之间都必须遵守的数据合同。

## 实验 B：导航纯逻辑闭环

输入是起点 `(0, 0, 0)`、目标 `(1, 0.5, 0)` 和固定时间间隔 `0.1 s`。

每一步的处理是：

1. `GoToPoseController` 比较当前位置与目标，输出机器人坐标系速度 `vx、vy、wz`。
2. `OdometryIntegrator` 假设机器人完美执行该速度，计算 0.1 秒后的新位姿。
3. 新位姿回到第 1 步，直到进入位置 5 cm、角度 5° 的容差范围。

输出是完整轨迹 `trajectory.csv`。预期第 27 步到达，最终约为 `(0.953927, 0.483627, 0)`；它没有精确等于目标，是因为“进入容差”就算完成。

## 实验 C：Cargo 规则

输入依次为橙、橙、紫。`Cargo.can_add()` 先判断，`Cargo.add()` 再更新数量。规则是总容量最多 3 块，紫色最多 1 块。

预期输出为橙色 2、紫色 1、总数 3；满载后继续加任何颜色都会被拒绝。另建空 Cargo 先放一块紫色，再尝试第二块紫色，也应被拒绝。
