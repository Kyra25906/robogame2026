## 三、下一步5条编程方向

### 方向1：实现 IMU 过期判断和轮速回退

#### 现有代码位置

文件：`ros2_ws/src/localization/localization/node.py`

当前已有：

```python
self.declare_parameter("imu_stale_s", 0.2)
self.latest_imu: Imu | None = None
```

但 `_on_odom()` 只要发现 `latest_imu` 不为空，就永远使用最后一帧 IMU：

```python
if self.latest_imu is not None:
    fused.twist.twist.angular.z = self.latest_imu.angular_velocity.z
```

这意味着 IMU 断开后，程序仍会把旧数据当成最新数据。

#### 建议修改

1. `import time`，使用 `time.monotonic()`，不要用系统日期计算超时。
2. 增加 `self.latest_imu_time: float | None = None`。
3. `_on_imu()` 收到消息时同时记录时间。
4. `_on_odom()` 计算 IMU 年龄。
5. 只有 `age <= imu_stale_s` 且角速度为有限数值时才使用 IMU。
6. IMU 不可用时保留 `/wheel_odom` 自己的角速度，不要填0，也不要继续使用旧IMU。
7. 只在“正常变过期”或“过期恢复正常”时各打印一次日志，避免每20 ms刷屏。

#### 为什么做

IMU线松动或驱动停止是现场常见问题。继续使用一帧旧角速度会让其他模块误以为传感器仍然正常。

#### 验收

- 新鲜IMU：输出角速度采用IMU。
- IMU年龄刚好等于阈值：行为有明确规定并经过测试。
- 过期IMU：回退到轮式里程计角速度。
- IMU恢复：重新采用新IMU。

### 方向4：编写导航自动验收和CSV记录脚本

`tools/navigation_acceptance.py`

#### 建议功能

脚本不负责控制算法，只负责重复测试：

1. 读取一组目标 `[x, y, yaw]`。
2. 发布 `/motion/goal`。

CSV至少包含：

```text
run_id,target_x,target_y,target_yaw,
final_x,final_y,final_yaw,
position_error_m,yaw_error_rad,duration_s,result,passed
```

第一版可以只支持预先写好的5个模拟目标，不要求做复杂界面。

#### 为什么做

手动看 `/pose` 很容易只记住成功的几次。自动记录能直接算出“10次成功8次”以及平均误差，真车标定时也能复用。

#### 验收

- 能完成至少5个目标的模拟测试。
- CSV每次测试恰好一行。
- 失败或超时也有记录。
- 脚本退出前保存文件。

## 五、先理解整条数据链

你负责的链路是：

```text
电控编码器/IMU
→ robot_bridge 发布 /wheel_odom 和 /imu/data
→ localization 发布 /pose
→ motion_control 比较 /pose 和 /motion/goal
→ motion_control 发布 /cmd_vel
→ robot_bridge 把速度发回电控
→ 到点后 motion_control 发布 /motion/result
→ mission_manager 才进入下一状态
```

这里有三种完全不同的量：

- `/motion/goal`：希望小车到哪里，单位是 m、m、rad。
- `/pose`：算法估计小车现在在哪里，单位也是 m、m、rad。
- `/cmd_vel`：这一瞬间底盘应该怎样运动，分别为 m/s、m/s、rad/s。

不要把目标位置直接当成速度，也不要用发送出去的速度冒充真实编码器反馈。

### IMU详细讲解：先知道它测到了什么

#### 1. IMU是什么

IMU是惯性测量单元。常见IMU内部至少包含：

- 陀螺仪：测量绕三个轴旋转的速度。
- 加速度计：测量三个轴方向的比力，静止时也会受到重力影响。
- 有些型号还包含磁力计：可以辅助判断地磁方向，但电机、钢结构和大电流会干扰它。

对当前平面移动的小车，最重要的是陀螺仪的 `angular_velocity.z`，也就是绕竖直轴旋转有多快。它的单位是 `rad/s`，不是角度，也不是 `°/s`。

例如：

```text
angular_velocity.z = 0.0       没有旋转
angular_velocity.z = 1.0       每秒约旋转57.3°
angular_velocity.z = 1.5708    每秒约旋转90°
```

#### 2. ROS2的IMU消息有哪些内容

`/imu/data` 使用 `sensor_msgs/msg/Imu`，主要字段是：

```text
header.stamp                 这份测量数据对应的时间
header.frame_id              IMU数据属于哪个坐标系
orientation x/y/z/w          姿态四元数
angular_velocity x/y/z       三轴角速度，单位rad/s
linear_acceleration x/y/z    三轴加速度，单位m/s²
三个 covariance             对各类数据不确定程度的描述
```

四元数的 `z` 不是偏航角，不能把 `orientation.z` 直接当作 yaw。四元数必须整体使用 `x、y、z、w` 转换成欧拉角。

有些IMU驱动只提供角速度和加速度，不提供可信姿态。如果某一类数据不可用，驱动应该通过协方差约定明确表示。收到消息不等于所有字段都有效，必须和电控确认实际填了哪些字段。

查看真实数据：

```bash
ros2 topic echo /imu/data
```

只看平面旋转角速度：

```bash
ros2 topic echo /imu/data --field angular_velocity.z
```

查看频率：

```bash
ros2 topic hz /imu/data
```

#### 3. 坐标轴和正方向

本项目计划遵守ROS常用约定：

```text
x轴：小车前方
y轴：小车左方
z轴：小车上方
绕z轴正方向：从上往下看为逆时针
```

所以小车原地逆时针旋转时，理想情况下 `angular_velocity.z` 应为正数；顺时针旋转应为负数。

但是IMU芯片可能横装、竖装或倒装，电控也可能在固件中交换过轴。不能只看变量叫 `z` 就默认方向正确，必须现场验证安装方向和转换关系。

如果方向错误，优先在一个明确的传感器坐标转换位置修正，并记录原因；不要在定位、控制、状态机三个地方分别乘 `-1`。

#### 4. 当前代码实际上怎样使用IMU

当前文件：

```text
ros2_ws/src/localization/localization/node.py
```

收到 `/imu/data` 后只保存最后一条消息：

```python
def _on_imu(self, msg: Imu) -> None:
    self.latest_imu = msg
```

收到 `/wheel_odom` 时复制轮式里程计，然后把输出中的角速度替换为IMU的z轴角速度：

```python
fused.twist.twist.angular.z = self.latest_imu.angular_velocity.z
```

这只能称为“使用IMU角速度作为观察值”，不能称为完整IMU融合，原因是当前代码：

- 没有对角速度积分得到新的 yaw。
- 没有用IMU姿态修正轮式里程计方向。
- 没有计算陀螺仪零偏。
- 没有处理协方差。
- 没有按传感器时间戳对齐轮速和IMU。
- 没有EKF或互补滤波。
- 当前真实串口状态解析尚未完成，模拟IMU只是由命令角速度生成。

因此模拟测试中IMU数值很漂亮，只能证明接口接通，不能证明真实定位精度。

#### 5. 为什么IMU会漂移

陀螺仪测量的是角速度。要得到朝向，需要不断积分：

```text
新yaw = 旧yaw + 角速度 × 时间间隔
```

假设静止时陀螺仪仍错误输出 `0.01 rad/s`，积分100秒后就会产生约 `1 rad`，也就是约57°的方向误差。这种静止时不为零的平均误差叫零偏。

零偏还会受到温度、供电、安装应力和启动状态影响。因此：

- 不能只在桌面测一次就永久写死。
- 上电后需要静止采样，估计零偏。
- 运动中通常需要轮式里程计、Tag或其他绝对观测纠正长期漂移。
- 加速度计能帮助判断倾斜，但不能单独稳定确定平面yaw。

#### 6. 时间戳和“过期”是两件事

需要区分两个时间：

- `msg.header.stamp`：传感器采样时刻，用于以后做数据同步和融合。
- `time.monotonic()`记录的收到时刻：用于判断这个话题多久没有更新。

为什么过期判断优先使用单调时钟：系统日期可能被网络校时突然调整，而单调时钟只向前走，适合计算“已经过去多少秒”。

配置：

```yaml
localization:
  ros__parameters:
    imu_stale_s: 0.2
```

如果IMU正常频率为20 Hz，一帧间隔约0.05秒，那么0.2秒大约相当于连续丢失4个周期。这个值只是初始设置，最终要根据真实回传频率和抖动调整。

正确行为应该是：

```text
IMU新鲜且数据有效
→ 使用IMU angular_velocity.z

IMU过期、NaN或无穷大
→ 不使用旧IMU
→ 回退到wheel_odom自己的angular.z
→ 记录一次警告

IMU恢复并收到新数据
→ 重新使用IMU
→ 记录一次恢复信息
```

过期以后不能继续发布最后一帧IMU值，也不能无条件填0。填0会谎报“机器人确定没有旋转”，回退到轮式里程计至少保留了另一个传感来源。

#### 7. 为什么还要检查NaN和无穷大

传感器初始化失败、串口拆包错误或除零都可能产生：

```text
NaN    不是一个有效数字
inf    正无穷大
-inf   负无穷大
```

比例控制如果收到 `NaN`，计算出来的 `/cmd_vel` 也可能变成 `NaN`。下位机如何解释这种浮点数据不可预测。因此定位模块必须在发布 `/pose` 前拒绝异常数据，让运动控制因位姿过期而明确停车。

#### 8. 现场第一次检查IMU的顺序

先架空或固定小车，不要一开始就运行自动任务。

1. 查看设备是否持续发布：

   ```bash
   ros2 topic hz /imu/data
   ```

2. 静止10～30秒，保存数据：

   ```bash
   ros2 bag record /imu/data /wheel_odom /pose
   ```

   静止时 `angular_velocity.z` 应围绕一个较小值波动，不能持续明显偏离0。加速度模长通常应接近重力加速度约9.8 m/s²，但各轴符号取决于驱动约定和安装方向。

3. 手动让小车逆时针缓慢转动，确认 `angular_velocity.z > 0`；顺时针应小于0。
4. 静止时轻推小车但不旋转，检查是否出现异常巨大的角速度尖峰。
5. 让小车旋转约360°，对比轮式里程计和IMU变化，记录方向、比例和漂移。
6. 运行过程中断开IMU数据源，检查超过 `imu_stale_s` 后是否回退并报警。
7. 恢复数据，检查是否自动恢复使用，而不是必须重启节点。

#### 9. 需要向电控确认的IMU信息

必须逐项得到回答：

- IMU具体型号和量程。
- 芯片在车上的安装方向。
- 固件输出的是原始值还是已换算的SI单位。
- 输出频率和实际最坏延迟。
- 是否包含角速度、加速度、四元数以及各自协方差。
- 是否做上电零偏校准，需要静止多久。
- 校准未完成、传感器故障和数据溢出如何表示。
- 时间戳来自MCU采样时刻还是Ubuntu接收时刻。
- 串口重连以后序号、时间和校准状态是否重置。

#### 10. 这一阶段IMU做到什么才算完成

远程阶段：

- 有纯函数测试覆盖新鲜、过期、恢复、NaN和无穷大。
- `imu_stale_s` 可以在YAML中配置。
- 旧IMU不会被无限使用。
- 日志能区分“IMU过期”和“IMU恢复”。

真车阶段：

- 频率、单位、轴方向和时间戳已确认。
- 静止零偏有数据记录。
- 顺/逆时针符号正确。
- 断开IMU后系统能够回退或停车，不盲目继续。
- 文档只写“角速度回退已完成”；在真正实现并验证滤波前，不写“IMU融合定位已完成”。

### 必测用例

| 编号 | 目标 `[x,y,yaw]` | 主要验证 |
|---|---|---|
| 1 | `[1.0,0.0,0.0]` | 正向运动 |
| 2 | `[1.0,0.5,0.0]` | 麦轮横向运动 |

## 九、代码改进的责任边界

按以下优先级处理。每改一项，必须先补自动测试，再修改节点。

### 4.1 使用 IMU 过期判断

当前 `localization/node.py` 虽然声明了 `imu_stale_s`，但没有真正判断最后一帧 IMU 是否过期。需要：

1. 收到 IMU 时记录本机单调时间。
2. 发布 `/pose` 前判断 IMU 年龄。
3. 只有未过期时才能使用 `angular_velocity.z`。
4. IMU 过期时保留轮式里程计角速度，并打印节流警告，不能继续假装 IMU 正常。

注意：当前版本并没有真正融合 IMU 朝向。不要把“替换角速度字段”写成“已完成融合定位”。

### 4.2 其余运动控制改进由我们完成

以下项目由我们这一侧实现，你只负责按第四、第五节的方法验收，不需要同时修改相同文件：

- `slow_radius` ROS参数化。
- `vx、vy、wz` 速度变化限制。
- 安全停止立即输出零速度。
- 一个目标只返回一次结果并在结束后清除。
- 与任务状态机和抓放对准之间的速度控制权协调。

其中 `slow_radius` 参数化、`vx/vy/wz` 速度变化限制和终止状态立即清零已于 2026-08-03 完成代码与自动测试；你拿到更新后重点做黑盒导航验收和真车参数测量，不需要重复实现。

如果你在验收中发现问题，只需提交最短复现步骤、预期和实际结果；除非我们明确分配，不要两边同时修改 `motion_control/node.py`。

## 十一、拿到真车后的测试顺序

必须架空轮子或放在支架上开始，速度上限先设为正式值的 20%～30%。

1. 不运行任务状态机，只检查串口能否持续30分钟收发。
2. 单独发送很小的正 `vx`，确认轮子组合和前进方向。
3. 单独发送正 `vy`，确认横移方向。
4. 单独发送正 `wz`，确认旋转方向。
5. 停止命令发布，确认 100～200 ms 内下位机独立停车。
6. 落地直行 1 m、横移 1 m、旋转 360°，各做10次。
7. 根据卷尺和角度标记校准轮径、几何参数、比例系数。
8. 最后才测试 `go_to_pose`，并从 0.1～0.2 m/s 的上限开始。

每次只改变一个方向或一个参数。发现方向相反时，先统一坐标定义，不要在多个模块里分别乘 `-1` 修补。
