## 三、下一步5条编程方向

### 方向1：实现 IMU 过期判断和轮速回退

#### 现有代码位置

文件：`ros2_ws/src/localization/localization/node.py`

当前已有：

```python
self.declare_parameter("imu_stale_s", 0.2)
self.latest_imu: Imu | None = None
```

但 `_on_odom()` 只要发现 `latest_imu` 不为空，就永远使用最后一帧 IMU：

```python
if self.latest_imu is not None:
    fused.twist.twist.angular.z = self.latest_imu.angular_velocity.z
```

这意味着 IMU 断开后，程序仍会把旧数据当成最新数据。

#### 建议修改

1. `import time`，使用 `time.monotonic()`，不要用系统日期计算超时。
2. 增加 `self.latest_imu_time: float | None = None`。
3. `_on_imu()` 收到消息时同时记录时间。
4. `_on_odom()` 计算 IMU 年龄。
5. 只有 `age <= imu_stale_s` 且角速度为有限数值时才使用 IMU。
6. IMU 不可用时保留 `/wheel_odom` 自己的角速度，不要填0，也不要继续使用旧IMU。
7. 只在“正常变过期”或“过期恢复正常”时各打印一次日志，避免每20 ms刷屏。

#### 为什么做

IMU线松动或驱动停止是现场常见问题。继续使用一帧旧角速度会让其他模块误以为传感器仍然正常。

#### 验收

- 新鲜IMU：输出角速度采用IMU。
- IMU年龄刚好等于阈值：行为有明确规定并经过测试。
- 过期IMU：回退到轮式里程计角速度。
- IMU恢复：重新采用新IMU。

### 方向3：拦截 NaN、无穷大和明显无效的定位输入

#### 改动文件

- `localization/quality.py`
- `localization/node.py`
- `tests/test_localization.py`

#### 建议修改

发布 `/pose` 前检查关键数据：

- `position.x、position.y、position.z`
- 四元数 `x、y、z、w`
- `linear.x、linear.y、angular.z`

如果出现 `NaN` 或正负无穷大：

1. 不发布这帧 `/pose`。
2. 不广播这帧 TF。
3. 打印一次明确警告。
4. 让 `motion_control` 依靠现有 `pose_stale_s` 自动进入 `LOCALIZATION_ERROR` 并停车。

四元数全为0也是无效姿态，应拒绝或先报告问题，不能直接当成正常方向。暂时不要擅自归一化所有异常四元数掩盖电控错误。

#### 为什么做

任何一个 `NaN` 进入比例控制器，都可能让 `/cmd_vel` 也变成 `NaN`，这是比“定位暂时中断”更危险的结果。

#### 验收

`tests/test_localization.py` 至少覆盖：

- 正常有限数据通过。
- `x=NaN` 被拒绝。
- `angular.z=inf` 被拒绝。
- 全零四元数被拒绝。
- 合法单位四元数通过。

### 方向4：编写导航自动验收和CSV记录脚本

#### 新建文件

`tools/navigation_acceptance.py`

#### 建议功能

脚本不负责控制算法，只负责重复测试：

1. 读取一组目标 `[x, y, yaw]`。
2. 发布 `/motion/goal`。
3. 订阅 `/pose` 和 `/motion/result`。
4. 记录开始时间、最终位姿和结果。
5. 计算位置误差：

   ```text
   sqrt((目标x-实际x)^2 + (目标y-实际y)^2)
   ```

6. 计算归一化后的角度误差。
7. 超过测试自身的最长等待时间后记录 `TEST_TIMEOUT`，不能无限等待。
8. 输出 `navigation_results.csv`。

CSV至少包含：

```text
run_id,target_x,target_y,target_yaw,
final_x,final_y,final_yaw,
position_error_m,yaw_error_rad,duration_s,result,passed
```

第一版可以只支持预先写好的5个模拟目标，不要求做复杂界面。

#### 为什么做

手动看 `/pose` 很容易只记住成功的几次。自动记录能直接算出“10次成功8次”以及平均误差，真车标定时也能复用。

#### 验收

- 能完成至少5个目标的模拟测试。
- CSV每次测试恰好一行。
- 失败或超时也有记录。
- 脚本退出前保存文件。

## 五、先理解整条数据链

你负责的链路是：

```text
电控编码器/IMU
→ robot_bridge 发布 /wheel_odom 和 /imu/data
→ localization 发布 /pose
→ motion_control 比较 /pose 和 /motion/goal
→ motion_control 发布 /cmd_vel
→ robot_bridge 把速度发回电控
→ 到点后 motion_control 发布 /motion/result
→ mission_manager 才进入下一状态
```

这里有三种完全不同的量：

- `/motion/goal`：希望小车到哪里，单位是 m、m、rad。
- `/pose`：算法估计小车现在在哪里，单位也是 m、m、rad。
- `/cmd_vel`：这一瞬间底盘应该怎样运动，分别为 m/s、m/s、rad/s。

不要把目标位置直接当成速度，也不要用发送出去的速度冒充真实编码器反馈。

- 电控是否直接接收 `vx、vy、wz`？
- 三者单位是否为 m/s、m/s、rad/s？
- 正方向分别是什么？正 `vy` 是向左还是向右？正 `wz` 是逆时针还是顺时针？
- 最大速度和最大加速度是多少？电控是否还会二次限幅？
- 速度命令期望频率是多少？20 Hz、50 Hz 还是其他？
- 超过多少毫秒没收到命令会自动置零？这个停车必须在下位机独立实现。

### 里程计反馈

- 返回四个轮子的原始编码器，还是已经计算好的 `vx、vy、wz`？
- 编码器单位、每圈计数、轮径、轮距和麦轮安装方式是什么？
- 回传频率和时间戳来源是什么？
- 上电、复位和通信重连后里程计是否归零？
- 数据溢出、丢帧或跳变如何表示？

### IMU反馈

- IMU型号、安装朝向、输出频率是什么？
- 返回角速度、欧拉角还是四元数？单位是什么？
- 是否在下位机做零偏校准？启动校准期间机器人能否移动？
- 如何报告校准完成和传感器故障？

### 串口与安全

- 串口设备、波特率、字节序、帧头、长度、序号、CRC范围是什么？
- 心跳包和状态包的消息类型编号是什么？
- USB拔出、CRC连续错误、Ubuntu死机时，下位机如何停车？
- 急停是否直接切断执行器，而不是等待ROS消息？

把结论发给我们，由我们统一写入 `docs/MCU_PROTOCOL.md`。必须标记“确认人、日期、固件版本”，口头但无法追溯的说法不能作为冻结协议。

## 十一、拿到真车后的测试顺序

必须架空轮子或放在支架上开始，速度上限先设为正式值的 20%～30%。

1. 不运行任务状态机，只检查串口能否持续30分钟收发。
2. 单独发送很小的正 `vx`，确认轮子组合和前进方向。
3. 单独发送正 `vy`，确认横移方向。
4. 单独发送正 `wz`，确认旋转方向。
5. 停止命令发布，确认 100～200 ms 内下位机独立停车。
6. 落地直行 1 m、横移 1 m、旋转 360°，各做10次。
7. 根据卷尺和角度标记校准轮径、几何参数、比例系数。
8. 最后才测试 `go_to_pose`，并从 0.1～0.2 m/s 的上限开始。

每次只改变一个方向或一个参数。发现方向相反时，先统一坐标定义，不要在多个模块里分别乘 `-1` 修补。

## 十二、你最终要交付什么

### 代码

- IMU过期判断及对应测试。
- 如果定位代码需要新的换算或校准参数，写入配置而不是散落常量。
- 不破坏原有导航和任务测试。

### 测试材料

- 23项基线测试结果；新增测试后总数应只增不减。
- 5种目标点、至少10轮的模拟导航记录。
- 越界、定位丢失、超时三种安全测试记录。
- 真车到位后，直行、横移、旋转和到点误差表。

### 协作文档

- 电控对速度、里程计、IMU和安全问题的逐条原始回复。
- 当前已知问题列表，每项写清影响、临时方案和负责人。
- 一段不超过3分钟的演示录像：发目标、运动、到点成功、越界停车。

## 十三、完成标准

远程阶段完成标准：

- 全部自动测试通过。
- 手动目标能正常到达。
- 越界、位姿过期、超时都会停车并给出明确结果。
- 参数都通过 YAML 调整，不临时改代码常量。

真车阶段完成标准：

- 通信连续30分钟稳定。
- 三个速度方向和单位正确。
- 停发命令后下位机能独立停车。
- 5个起点各测试2次，至少8次到点成功。
- 暂定位置误差小于5 cm，角度误差小于5°；如果机械搭建需要更高精度，再根据实测收紧。

在这些项目通过之前，不开始 Nav2、复杂地图、多块路径优化或三层塔策略。
