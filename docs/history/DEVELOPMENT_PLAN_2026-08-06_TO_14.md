# RoboGame2026 开发计划：2026 年 8 月 6 日至 14 日

适用阶段：8 月 6～8 日远程开发，8 月 9～14 日现场开发

## 一、总体目标

在 8 月 14 日结束前，尽可能完成并验证：

```text
真实相机输入
→ 方块检测与目标选择
→ 小车接近和对准
→ 真实抓取
→ 抓取证据确认
→ 抬升与搬运
→ 真实释放
→ 局部撤退
→ 放置稳定验证
→ 单方块真实闭环
→ 多方块任务联调
→ 重复性与异常测试
```

当前已经完成的是 ROS2 单方块模拟软件闭环。接下来不能把主要时间继续投入模拟功能扩展，而应逐步把模拟边界替换为真实相机、真实机构和真实场地数据。

## 二、执行原则

### 1. 每天只设置一个主要验收目标

当天新增功能如果不能帮助主要目标通过，就放入待办，不立即实现。

### 2. 每项结论必须有证据

证据可以是：

- 测试命令和终端输出；
- 原始视频与标注视频；
- JSONL 数据和验收报告；
- 参数配置文件；
- 现场照片和尺寸记录；
- Git commit；
- 多次重复实验的统计表。

### 3. 参数修改必须可追溯

每次现场调参记录：

```text
修改前参数
修改原因
测试条件
修改后结果
对应数据文件
是否保留
```

### 4. 每天结束前固定做四件事

1. 保存当天数据和日志；
2. 运行当天最低回归测试；
3. 更新开发记录与待确认清单；
4. 创建清晰的本地 Git 检查点，确认后再推送功能分支。

### 5. 现场最后两天原则上停止大规模重构

8 月 13 日开始以稳定性、恢复策略和文档为主。除阻断闭环的严重问题外，不再重写架构或增加非必要功能。

## 三、全项目覆盖审计与优先级修正

这不是一个单纯的视觉项目。完整机器人至少包含下面八条功能链：

| 功能链 | 当前基础 | 仍需完成或验证 | 优先级 |
|---|---|---|---|
| 规则与任务策略 | 已有任务状态机和颜色顺序 | 按真实比赛流程核对容量、顺序、重试和完成条件 | 必须 |
| 底层通信与状态 | 有串口帧和模拟状态骨架 | MCU 真实载荷、心跳、错误码、物理启动、急停和状态解析 | 最高 |
| 底盘控制 | 有速度命令、控制器和模拟里程计 | 真车方向、速度、加速度、停止距离、边界和失联停车 | 最高 |
| 定位与里程计 | 有定位节点和算法测试 | 编码器/IMU 单位、方向、时间戳、过期检查和现场漂移 | 最高 |
| 视觉感知 | 有 HSV 检测、时间滤波和单段报告 | 真实相机标定、批量验收、ROI、光照和遮挡 | 必须 |
| 机械臂与夹爪 | 有模拟服务和抓放闭环 | 真实 `GRAB/LIFT/RELEASE/STOP` 协议、错误码与取消能力 | 最高 |
| 放置结果验证 | 模拟四终态已通过 | 真实视觉证据、撤退距离和现场阈值 | 必须 |
| 启动部署与安全 | 有 launch 和部分安全检查 | 硬件 launch、物理启动、急停、通信丢失、日志和恢复说明 | 最高 |

当前最大的阻塞项是：

```text
robot_bridge 的真实 MCU 状态和机构载荷尚未实现
```

如果这一项没有按时确认，即使视觉模块完成，也无法形成真实机器人闭环。因此远程三天的优先顺序调整为：

```text
真实接口合同与协议样例
→ robot_bridge 可测试的编码/解码适配器
→ 定位、运动和安全离线测试
→ 视觉批量验收与证据适配
→ 现场工具和数据模板
```

以下每日计划按这个全系统优先级执行。视觉批量工具仍然重要，但不能占用全部远程时间。

## 五、8 月 7 日：真实桥接协议骨架与视觉证据接口

### 当日主要目标

让真实 MCU 数据能够在无硬件或录制样例下被编码、解码和测试；同时定义视觉结果如何转换为稳定观察证据。

### 具体清单

- [ ] 根据已确认字段实现或补齐纯 Python 状态载荷解码器；
- [ ] 为速度、停止、机构和升降命令准备真实载荷编码器；
- [ ] 使用固定字节样例测试 CRC、长度、单位、正负号和错误码；
- [ ] 保持串口 I/O 与协议编码/解码逻辑分离；
- [ ] 对尚未确认的真实机构命令继续安全拒绝，不伪造成功；
- [ ] 恢复或重新实现轻量时间段标注入口；
- [ ] 支持填写片段名称、`start_s`、`end_s` 和 `expected`；
- [ ] 支持新增、修改、删除片段；
- [ ] 保存为批量验收 manifest；
- [ ] 不修改原始视频；
- [ ] 明确 `QUALIFIED / FAILED / UNAVAILABLE` 的输入字段；
- [ ] 定义最低字段：时间戳、目标是否可见、位置、置信度、ROI、数据新鲜度；
- [ ] 写出初版证据转换规则，但把现场阈值保持为配置项；
- [ ] 为证据适配器编写纯 Python 单元测试；
- [ ] 记录仍需现场确认的 ROI、位移、倾斜和遮挡阈值。

### 推荐证据规则草案

```text
目标可见 + 位于 ROI + 位置变化在阈值内
→ QUALIFIED

目标可见 + 明确离开 ROI / 明显位移 / 倒塌特征
→ FAILED

目标不可见 / 遮挡 / 图像过期 / 置信度不足
→ UNAVAILABLE
```

### 当天必须产出的证据

- 协议编码/解码源码与固定样例测试；
- 未确认协议字段清单；
- 可保存的时间段标注文件；
- 一份示例 manifest；
- 视觉证据接口说明；
- 证据转换单元测试；
- 现场待定阈值表。

### 学习重点

- 二进制协议、字节序、单位和 CRC；
- 用户输入校验；
- 数据模型与界面分离；
- 为什么 `UNAVAILABLE` 不等于 `FAILED`；
- 如何把现场未知量做成参数。

### 当天停止边界

真实协议至少应能由固定样例证明编码和解码一致；视觉工具以“队友能保存正确配置”为目标，不追求复杂 GUI。

## 十五、关键风险与预案

| 风险 | 预案 |
|---|---|
| 相机严重遮挡放置区 | 调整安装角度或撤退姿态；保留 `INCONCLUSIVE`，不误报成功 |
| 视觉现场误检严重 | 回到录像离线验收；限制 ROI；降低自动运动范围 |
| 真实串口状态解析未完成 | 将其提升为最高优先级；先冻结最小状态字段，不继续扩展上层功能 |
| 底盘方向或停止不可靠 | 禁止自动追踪；架空或低速逐轴检查，先修安全链路 |
| 定位漂移无法支持绝对航点 | 缩短移动距离、增加场地参考或采用可验证的降级策略 |
| 真实机构协议迟迟未确认 | 保留模拟桥；先用手动服务逐项验收；书面冻结最小接口 |
| 机构没有可靠抓取传感器 | 组合服务结果、夹爪状态与视觉证据，并明确置信边界 |
| 底层不能真正取消动作 | 软件停止后明确警告；急停由硬件链路保证 |
| VMware/上位机状态消息抖动 | 记录消息间隔；区分模拟和真机参数，不随意放宽真机阈值 |
| 多方块任务不稳定 | 先保证单方块；必要时降级演示范围，不牺牲安全性 |
| 最后两天仍频繁改架构 | 冻结接口，只修阻断和高频错误 |
