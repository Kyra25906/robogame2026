# RoboGame2026 开发日志：单方块模拟闭环

日期：2026-08-04

开发方式：Windows 编写与测试，Ubuntu 虚拟机运行 ROS2 验收

## 一、今天的目标

今天的主要目标，是把原来只到“抓取、抬升、释放”的模拟流程，扩展为一个可以判断放置结果的单方块软件闭环：

```text
PICK
→ 抓取证据通过
→ LIFT
→ RELEASE
→ 放置初步验证
→ 局部撤退
→ 撤退完成证据
→ 稳定观察
→ STABLE / FAILED / INCONCLUSIVE / CANCELLED
```

这里完成的是 **ROS2 模拟软件闭环**，还不是摄像头、机械臂和真实方块共同参与的现场物理闭环。

### 2. 增加放置后的稳定观察判定器

在不依赖 ROS2 的 `robogame_core` 中加入了稳定观察器。它接收带时间戳的放置证据，并输出：

- `OBSERVING`：仍在收集证据；
- `STABLE`：合格证据累计达到要求；
- `FAILED`：明确观察到放置失败；
- `INCONCLUSIVE`：观察超时，但证据仍不足。

默认参数为：

```yaml
placement_stable_duration_s: 3.0
placement_observation_timeout_s: 6.0
placement_max_unavailable_gap_s: 0.0
```

稳定时间根据时间戳计算，不根据固定帧数计算，因此不会因为摄像头掉帧或帧率变化而错误估计 3 秒。

### 3. 将流程状态与机构操作分开

机构操作仍然保持为：

```text
GRAB
LIFT
RELEASE
```

流程状态新增：

```text
RETREATING
WAITING_RETREAT_EVIDENCE
OBSERVING_STABILITY
```

这样可以清楚地区分：

- “当前流程进行到哪里”；
- “当前机构正在执行什么动作”。

以后机械结构发生变化时，可以修改动作实现，而不必推翻任务流程。

### 4. 增加独立的撤退完成证据

在 `RobotStatus` 中加入：

```text
bool retreat_complete
```

模拟桥增加了：

```text
/chassis/retreat
```

新的规则是：

```text
RELEASE 完成
→ retreat_complete = false
→ 调用局部撤退服务
→ 收到新的 retreat_complete = true
→ 才开始稳定观察
```

这避免了夹爪仍接触或遮挡方块时，系统就提前开始累计稳定时间。

这里的“局部撤退”是放置后的短距离避让，不等同于任务管理器中所有方块放完后的任务级 `RETREAT`。

### 5. 增加短暂视觉中断容忍参数

放置证据被分为：

- `QUALIFIED`：当前观察合格；
- `FAILED`：明确失败；
- `UNAVAILABLE`：被遮挡、图像缺失或置信度不足。

短暂 `UNAVAILABLE` 的规则是：

```text
中断时间不超过 placement_max_unavailable_gap_s
→ 保留之前的稳定进度
→ 中断期间不计入稳定时间

中断时间超过阈值
→ 清除已有进度
→ 恢复可见后重新累计
```

当前默认值仍为 `0.0`，因为还没有现场录像支持选择合理的非零阈值。以后可以只修改 YAML 或 launch 参数，不需要修改代码。

### 6. 接入 manipulator_client

`manipulator_client` 现在能够执行：

```text
放置验证通过
→ 请求局部撤退
→ 等待新的撤退状态
→ 创建稳定观察器
→ 发布最终结果
```

抓取成功继续输出：

```text
SUCCESS
```

放置任务可能输出：

```text
STABLE
FAILED: placement became unstable
INCONCLUSIVE: stable placement could not be confirmed
CANCELLED: software workflow stopped
```

只有 `STABLE` 才会增加已放置层数。

### 7. 完成人为取消设计

增加了稳定观察期间的取消测试：

```text
开始稳定观察
→ 发布 CANCEL
→ 返回 CANCELLED
→ 不继续等待 3 秒
→ 不输出 STABLE
```

撤退服务正在执行时取消，也会明确提示：软件流程已经停止，但底层撤退服务可能仍然完成。

### 8. 增加摄像头安装和现场确认清单

在 `docs/vision/VISION_MODULE.md` 中记录了真实闭环依赖的可观测性假设，包括：

- 摄像头型号、分辨率、帧率和视场角；
- 安装高度、俯仰角和到放置区的距离；
- 机械臂释放位与收回位的遮挡轮廓；
- 最小局部撤退距离；
- 放置区域 ROI；
- 方块允许位移和倾斜阈值；
- 相机与车体振动稳定时间；
- 光照、反光和赛场遮挡；
- `INCONCLUSIVE` 后的恢复动作。

文档同时明确：`INCONCLUSIVE` 表示系统证据不足，不代表真实方块一定不稳定。

## 三、实现了什么功能

### 单方块模拟闭环

ROS2 模拟环境已经支持四种终态：

| 场景 | 终态 | 行为 |
|---|---|---|
| 放置后持续合格 | `STABLE` | 连续观察满足要求后成功 |
| 明确移位或倒塌 | `FAILED` | 立即失败，不等待 3 秒 |
| 持续无法获得证据 | `INCONCLUSIVE` | 达到总观察超时后结束 |
| 用户主动取消 | `CANCELLED` | 立即停止软件流程，不误报成功 |

### 可调参数

模拟 smoke launch 现在可以从命令行调整：

```text
placement_evidence_policy
placement_stable_duration_s
placement_observation_timeout_s
placement_max_unavailable_gap_s
expected_place_result
cancel_during_stability
cancel_delay_s
```

因此可以在不修改源码的情况下测试正常、失败、证据不足和取消路径。

## 五、今天学到的知识

### 1. 闭环不等于“动作执行完”

`RELEASE` 成功只能证明夹爪执行了释放动作，不能证明方块最终稳定。真正的闭环还需要环境反馈和最终结果判断。

### 2. 动作、状态和证据是三个不同概念

- 动作：系统要求机构做什么；
- 状态：任务流程进行到哪里；
- 证据：传感器能证明什么。

把三者分开，可以降低机构变化对上层流程的影响。

### 3. 不能把“看不见”当成“失败”

相机被遮挡时，方块可能仍然稳定。因此需要区分：

```text
明确不合格 → FAILED
证据不足   → INCONCLUSIVE
```

### 4. 时间判断应使用时间戳

“90 帧约等于 3 秒”依赖固定 30 FPS。虚拟机、相机和算法都可能掉帧，因此应使用单调时间戳计算真实持续时间。

### 5. 短暂丢失证据不应被算作稳定时间

允许短暂遮挡时，可以保留此前进度，但遮挡本身不能加入稳定时间，否则会高估实际观察时长。

### 6. 安全错误应具有更高优先级

在视觉观察期间失去机器人通信时，应优先报告 `COMMUNICATION_ERROR`，而不是继续等待并输出 `INCONCLUSIVE`。

### 7. 集成测试会发现单元测试看不到的问题

第一次 ROS2 smoke 测试发现了启动竞态：smoke 收到第一条状态后立即发令，而 `manipulator_client` 可能还没有收到状态。解决方法是在测试驱动中增加短暂同步窗口，而不是放宽安全检查。

### 8. 跨系统同步前必须备份和校验

Windows 与 Ubuntu 都有未提交修改时，不能直接覆盖。应先备份，再精确同步，最后用 SHA256 确认文件一致。

### 9. Git 应使用明确的暂存白名单

本次提交使用明确文件列表，没有使用 `git add .`，因此录像、报告、Word 临时文件、课程输出和调试数据没有进入仓库。
