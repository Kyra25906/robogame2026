> 用途：**任何人（含另一个 Agent、以及明天的你）只看这一份文档，就能知道

> 约定：
> 1. 每轮结束追加一节，不改写历史节（错了就再写一节纠正，保留过程）；
> 2. 每节必须写清：范围 / 改了哪些文件 / 证据（可复现命令 + 实际结果）/

> 4. 结论强度只跟证据一致：纯逻辑测试 ≠ 节点行为 ≠ 真车。

## R3（B3-2 前置）网页里程计标定：三问分离 ｜ 2026-09-17

**背景**：用户提出「只验证了给速度、给时间、距离基本一致」，需要网页里再测。
复核发现现有「底盘定距测试」是**用里程计闭环停车**，所以「已前进 = 目标」是自证，
**证明不了里程计准不准**。

**产出**
- `tools/odom_calibration.py`（新，纯逻辑）：把三个问题分开算并各自下结论——
  ① 开环（命令速度×时间 vs 尺量）；② **自洽**（里程计等效速度 ÷ 命令速度，
  **不用尺子**就能看出被放大几倍）；③ 标度（尺量 ÷ 里程计）。样本 <3 组或
  组间波动 >3% 时**拒绝给标度**；接近整数比时提示先查固件常量。
- `tools/field_dashboard.py`：`/api/odom/record`（尺量**可留空**，用于累积自洽
  样本）、`/api/odom/reset`、snapshot 增加 `odom_calibration` 与候选；中断的
  定距试验清掉候选（防止把旧数据当本次数据）。
- `tools/field_dashboard_web/odom_panel.js` + `index.html` + `app.js`：新面板。

**证据**：`tests.test_odom_calibration` 22 OK、`tests.test_dashboard_odom` 13 OK
（**行为级**：真实 `DashboardController` + Mock ROS，真跑「定距→补录尺量→汇总」）、
`node tmp\odom_panel_check.js` 5/5；全量 1128 项，仅 2 个已知沙箱错误。

**设计修正（留痕）**：初版要求「必须填尺量才能记录」，把最有用的②锁住了 → 改为
尺量可留空。

**不能证明**：真车里程计准不准——只有场地跑 3 组才知道。

## R5（B3-3）每段巡线限速 + 坡道段（C3 接入） ｜ 2026-09-17

**范围**：把 C3 的 `RampController` 接进路线执行；顺带补一个此前没被发现的缺口。

**发现（真实缺口）**：路线登记表里每段都写了限速（0.20 / 0.25 / 0.15），但巡线节点
一直用自己参数里的 `vx_base`——**等于全路段一个速度**，计划里的分段限速从未生效。
本轮由任务层按段下发。

**产出**
- `mission_dispatch.py`：新增 `LineCommand` + `line_command_for()` / `parse_line_command()`
  / `effective_line_speed()`。巡线段下发本段限速；坡道段额外带 `RampProfile`（C3）。
- `mission_manager`：新增发布 `/mission/line`（进入段下发一次，非巡线段发空串清除，
  终态也清除）；新增**重试时重发本段命令**——打滑卡住后巡线节点保持零速，
  只重置计时是叫不醒它的；`/line_follow/status` 里出现 `STUCK` 连续 3 次 →
  走既有的 `action_failed` 重试路径（`MECHANISM_ERROR: ramp stuck`）。
- `line_follow_node`：订阅 `/mission/line` 与 `/wheel_odom`；`_apply_line_limits()`
  按本段限速裁剪 PD 输出，坡道段把输出穿过 `RampController`（限速/加速度/打滑降速）；
  轮速**过期时不做打滑判定**（宁可不判，也不误判停车）；状态串新增
  `line_limit_mps / ramp_kind / ramp_decision / measured_speed_mps`。
- `/mission/route` 载荷与网页面板：显示「本段限速」「坡道正常/SLIPPING/STUCK」。

**证据**
- `tests.test_mission_dispatch` 30 → 40 OK（新增 10 项：分段限速、只有坡道段带
  profile、JSON 往返、坏输入拒收、取更严格的限速、坡道限速/下坡更保守/轮速跟不上
  → SLIPPING → STUCK 停车、正常轮速不误报）。
- `tests.test_mission_manager_route` 35 → 43 OK（新增 8 项接线断言，含「重试必须
  重发命令」「STUCK 触发重试」「轮速过期禁用打滑判定」）。
- `node tmp\route_panel_check.js` 14/14；全量 **1154** 项，仅 2 个已知沙箱错误。

**登记式测试更新**：巡线节点新增订阅 `/mission/line` → 两张独立巡线图的已解释缺口
变为 `{active_source, turn, line}`（原因同 R4）。

**必须说清的边界（已写进代码注释与现场清单）**
1. 打滑检测用**轮速**里程计：它看不到「轮子空转、车不走」（编码器量的是轮子转了
   多少）。它能抓的是「轮速跟不上命令」（上坡上不去的典型表现）。真抓空转需要
   IMU 俯仰/加速度或视觉，而 `imu_valid` 目前为 false。
2. `vx_base` 同时是**全局兜底上限**：生效限速取 `min(本段限速, vx_base)`。
   要让 S02 的 0.25 真正生效，节点参数 `vx_base` 必须 ≥ 0.25。

**不能证明**：坡道限速/打滑阈值是否合适（14° 实坡未测）；节点行为仍是 AST 断言。

**下一步**：W02 连取 3 块（槽间微移）+ W04 搭 2 层动作序列 → B4 整栈自主启动。
