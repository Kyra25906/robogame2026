# 算法给电控与机械的接口说明

## 1. 文档目的

这份文档用于算法、电控和机械三方冻结接口。它不要求电控或机械理解任务规划、视觉识别等内部算法，只需要把“收到什么、执行什么、返回什么、异常时怎样停”确认清楚。

接口状态分为三类：

- **已定义**：代码已经采用，可以按本文联调。
- **待三方确认**：本文给出建议，但必须实测方向、单位或安全行为后签字确认。
- **未定义，禁止猜测**：真实载荷或错误码尚未冻结，算法不会自行假设。

## 2. 系统边界

```text
任务/视觉/运动算法
        |
        | ROS2: /cmd_vel、机构服务
        v
robot_bridge（上位机协议转换）
        |
        | 串口帧
        v
电控 MCU ───── 底盘电机、编码器、IMU、急停
        |
        └───── 夹爪、升降机构、限位/电流/位置传感器
```

算法负责决定目标速度和动作顺序；电控负责实时执行、硬件限幅、通信失联停车和传感器回传；机械负责说明动作约束、有效行程、完成判据和故障判据。

## 3. 已定义的ROS2接口

### 3.1 底盘速度

算法发布：

```text
话题：/cmd_vel
类型：geometry_msgs/msg/Twist
```

有效字段：

| 字段 | 含义 | 建议单位与正方向 | 状态 |
|---|---|---|---|
| `linear.x` | 车体前后速度 `vx` | m/s，车头方向为正 | 待实车确认正方向 |
| `linear.y` | 车体左右速度 `vy` | m/s，车体左方为正 | 待实车确认正方向 |
| `angular.z` | 原地旋转速度 `wz` | rad/s，逆时针为正 | 待实车确认正方向 |

其余 Twist 字段当前不使用，应忽略或保持为零。

电控必须确认：

- 麦轮编号、安装方向和正负号；
- `vx、vy、wz`到各轮速度的转换由上位机还是MCU完成；
- 三个方向分别允许的最大速度、最大加速度和死区；
- 同时平移和旋转时如何限幅；
- 收到NaN、无穷大、超限值或未知模式时如何拒绝。

### 3.2 轮式里程计

电控或桥接节点发布：

```text
话题：/wheel_odom
类型：nav_msgs/msg/Odometry
```

真实模式必须来自编码器/轮速反馈，不能使用上位机下发的目标速度冒充测量值。至少需要有效时间戳以及车体坐标系中的：

```text
twist.twist.linear.x
twist.twist.linear.y
twist.twist.angular.z
```

待确认：编码器单位、减速比、轮径、轮距、轮速正方向、更新频率、掉帧和溢出处理。

### 3.3 IMU

电控或桥接节点发布：

```text
话题：/imu/data
类型：sensor_msgs/msg/Imu
```

当前定位至少会使用 `angular_velocity.z`。单位必须是 `rad/s`，不能直接发送度每秒而不转换。时间戳应表示传感器采样时间，不应全部填零。

待确认：IMU安装方向、零偏、上电静止校准时间、输出频率、顺/逆时针正负号、异常值和数据过期行为。完整姿态、协方差和加速度字段如果暂时无效，应按照ROS2消息约定明确标记，不能填看似正常的假数据。

### 3.4 机器人状态

桥接节点发布：

```text
话题：/robot/status
类型：robogame_interfaces/msg/RobotStatus
```

字段：

| 字段 | 电控/机械需要表达的含义 |
|---|---|
| `communication_ok` | MCU通信、状态更新和关键执行链路是否健康 |
| `emergency_stop` | 硬件急停是否按下或安全链是否断开 |
| `physical_start` | 比赛实体启动信号是否有效 |
| `gripper_closed` | 夹爪位置是否处于闭合状态；不等同于抓到方块 |
| `cube_present` | 是否有独立证据确认夹爪内存在方块 |
| `mechanism_fault` | 夹爪、升降、限位、电机或驱动是否故障 |
| `battery_voltage` | 实际电池电压，单位V |
| `error_code` | 冻结后的机器可判定错误码 |
| `detail` | 供日志显示的简短说明，不作为唯一控制依据 |

算法侧超过约0.30秒没有收到新状态会拒绝导航和抓放；这只是软件第二道保护，不能代替电控硬件失联停车。

### 3.5 夹爪和升降服务

当前ROS2服务已经定义：

```text
/gripper/grab       robogame_interfaces/srv/ExecuteMechanism
/gripper/release    robogame_interfaces/srv/ExecuteMechanism
/lift/set_height    robogame_interfaces/srv/SetLiftHeight
/chassis/stop       停车服务入口
```

抓取/释放请求与响应：

```text
请求：command:string, timeout_s:float32
响应：success:bool, error_code:uint16, duration_s:float32, detail:string
```

升降请求与响应：

```text
请求：height_m:float32, timeout_s:float32
响应：success:bool, error_code:uint16, duration_s:float32, detail:string
```

`success=true`必须表示机构已经达到可验证的最终状态，不能表示“命令已收到”或“电机已经开始转”。

## 4. 已定义的串口外层协议

所有多字节数使用小端序：

```text
AA 55 | version:u8 | type:u8 | sequence:u16 | payload_length:u16 | payload | crc16:u16
```

- CRC：CRC-16/CCITT-FALSE；多项式 `0x1021`；初值 `0xFFFF`。
- 最大载荷：512字节。
- 序号达到65535后回绕。
- 校验失败的帧必须丢弃，接收端从下一个 `AA 55` 重新同步。

已分配消息类型：

| 类型 | 方向 | 内容 | 状态 |
|---|---|---|---|
| `0x01` | 上位机 → MCU | `vx:f32, vy:f32, wz:f32, mode:u8` | 已定义 |
| `0x02` | 上位机 → MCU | 机构命令 | 载荷未定义，禁止实机启用 |
| `0x03` | 双向 | 心跳 | 载荷和应答细节待确认 |
| `0x81` | MCU → 上位机 | RobotStatus | 载荷未定义 |
| `0x82` | MCU → 上位机 | 轮式里程计 | 载荷未定义 |
| `0x83` | MCU → 上位机 | IMU采样 | 载荷未定义 |

当前代码能发送 `0x01`，也能按照帧头、长度和CRC从字节流中提取回传帧。`0x02、0x81、0x82、0x83`的真实载荷必须由三方共同形成逐字节字段表后再实现。

## 5. 电控必须独立保证的安全行为

以下安全行为必须在MCU/驱动层成立，即使Ubuntu死机、ROS2崩溃或串口线拔掉也必须有效：

1. 连续150 ms没有收到合法速度命令时，所有底盘目标速度归零。
2. 重连后不得恢复断线前的旧速度或旧机构动作。
3. 硬件急停直接禁止底盘和机构输出，不能等待上位机确认。
4. 拒绝NaN、无穷大、超限速度、错误长度、错误版本和CRC失败帧。
5. 上电默认安全，未收到实体启动和合法命令前不得运动。
6. MCU看门狗复位后保持停车，并报告复位原因。
7. 限位触发、堵转、过流、欠压或驱动故障时停止相关机构并返回明确故障。

算法的软件急停、状态过期检查和零速度命令只是额外保护，不是硬件安全链的替代品。

## 6. 机械团队必须给出的参数和判据

### 6.1 夹爪

需要确认：

- 张开和闭合的机械极限；
- 最大允许电流、速度、力或PWM；
- 一次抓取的正常耗时和最长耗时；
- 如何区分“闭合但没抓到”和“确实抓到方块”；
- 抓取完成证据使用限位、电流、编码器位置还是独立传感器；
- 方块运输中掉落如何检测；
- 急停后夹爪保持、松开还是失电，是否会掉块。

### 6.2 升降机构

需要确认：

- 零点建立方式和上电回零流程；
- 有效行程、上下硬限位和软限位；
- `height_m`表示夹爪基准点、方块底面还是机构滑块位置；
- 第一、二、三层的实测目标高度；
- 位置误差允许值和稳定时间；
- 是否允许升降与底盘或夹爪同时动作；
- 断电、急停和通信中断时是否可能自由下落。

### 6.3 每条机构命令的结果

每条命令必须最终返回以下三类之一：

```text
成功：到达目标且传感器证据有效
失败：明确错误码，例如限位、过流、堵转、未抓到、传感器故障
超时：在约定最长时间内没有完成，机构已经进入安全状态
```

只返回“已收到”不算动作结果。算法需要最终结果才能决定继续任务、重试还是停车。

## 7. 必须共同冻结的字段表

每个串口消息都应形成如下逐字节表，三方确认后再写代码：

| 偏移 | 长度 | 类型 | 字段 | 单位 | 范围 | 说明 |
|---:|---:|---|---|---|---|---|
| 0 | 示例 | `f32/u16/u8` | 字段名 | SI单位 | 合法范围 | 正方向、无效值 |

还必须冻结：

- 协议版本和升级兼容方式；
- 心跳周期与通信故障判定时间；
- 命令序号、重复命令和应答如何匹配；
- 机构命令是否幂等、怎样取消；
- 所有错误码的数值、含义和恢复条件；
- USB/串口重连后谁先握手、何时允许运动。

## 8. 推荐联调顺序

不要第一次联调就运行完整任务。按以下顺序逐级验收：

1. **断电检查**：只接通信，确认帧头、长度、CRC、序号和日志。
2. **架空轮子**：分别发送很小的 `+vx、-vx、+vy、-vy、+wz、-wz`，核对每个轮子的方向。
3. **超时停车**：持续发送低速命令后拔掉串口或停止发送，确认150 ms内MCU独立归零。
4. **急停**：低速运动时按下硬件急停，确认底盘和机构不依赖Ubuntu立即停止。
5. **里程计/IMU**：手动前推、横移、旋转，核对单位、正负号、频率和时间戳。
6. **单机构空载**：分别测试夹爪张开、闭合、升降和限位，不运行底盘。
7. **机构带载**：使用正式方块验证抓到、没抓到、掉块、堵转和超时反馈。
8. **软件安全联锁**：停止 `/robot/status`、制造通信错误和机构故障，确认算法拒绝运动。
9. **低速联合闭环**：最后才运行视觉对准、抓取、搬运和放置。

每一步都要记录命令、时间、实际动作、返回状态、错误码和视频。前一步未通过，不进入下一步。

## 9. 当前不能宣称完成的内容

在真实字段表和实机验收完成前，以下内容仍未完成：

- MCU状态、真实编码器里程计和IMU载荷解析；
- 真实抓取、释放和升降命令载荷；
- 机构完成反馈、取消、错误码和幂等行为；
- 真实通信中断、急停和看门狗测试；
- 三层高度、夹爪抓取证据和掉块检测；
- 真车速度方向、限幅、里程计比例和IMU方向标定。

当前 `robot_bridge` 的模拟模式用于软件流程开发。真实模式在未冻结协议时主动拒绝机构服务，这是安全设计，不应绕过。

## 10. 三方确认清单

正式启用真实硬件前，请算法、电控、机械负责人共同确认：

- [ ] `vx、vy、wz`单位、正方向、最大值和超时行为
- [ ] 四轮编号、安装方向、轮径、减速比和编码器分辨率
- [ ] IMU安装方向、单位、频率、时间戳和上电校准
- [ ] `0x02、0x03、0x81、0x82、0x83`逐字节载荷表
- [ ] 心跳、序号、重复命令、应答、重连和版本策略
- [ ] 急停、看门狗、150 ms失联停车和上电默认安全
- [ ] 夹爪完成、未抓到、掉块、堵转和过流判据
- [ ] 升降零点、行程、三层基准、限位和断电行为
- [ ] 统一错误码表及每个错误的恢复方式
- [ ] 分级联调记录和最终三方签字
