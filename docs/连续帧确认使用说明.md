# 连续帧确认：新手使用说明

## 它解决什么问题

单帧识别可能因为反光、运动模糊或相似颜色突然报出一个假目标。如果这一帧立刻交给底盘，小车可能突然横移。连续帧确认要求目标在相近位置连续出现几帧，才把它发布给抓取控制。

工作顺序：

```text
原始HSV检测
→ 判断这一帧目标是否接近上一帧位置
→ 连续计数达到门限
→ 发布确认目标
→ 对位置、距离和置信度做平滑
```

核心代码：`cube_perception/temporal_filter.py`。

## 四个可控参数

参数位于：

- `cube_perception/config/vision_default.json`：独立照片/视频工具使用；
- `robogame_bringup/config/robot.yaml`：ROS2节点使用。

### `confirm_frames`

连续多少帧后才相信目标。默认 `3`。

- 调大：更稳，但发现目标更慢；
- 调小：反应更快，但更容易接受偶发误检；
- 建议：先用3，现场帧率低于10 FPS时可考虑2。

### `match_distance_px`

当前目标和上一帧相差多少像素以内，仍算同一个目标。默认 `80`，按720p画面设计。

- 太小：机器人或方块稍微移动就重新计数；
- 太大：两个相邻同色方块可能被当成同一个；
- 建议：先在视频中观察相邻帧中心移动量，设置为正常移动量的2～3倍。

### `smoothing_alpha`

新一帧对最终结果的影响比例。默认 `0.4`。

- 接近1：响应快，平滑弱；
- 接近0：更平滑，但跟随变慢；
- 建议范围：`0.3～0.6`。

### `max_missed_frames`

目标消失后，旧位置最多保留多少帧用于重新匹配。默认 `3`。注意：消失帧不会输出旧目标，连续确认计数也会立即归零。

## 怎样直接看见确认过程

运行正常检测：

```bash
ros2 run cube_perception cube_detector \
  --source your_video.mp4 \
  --config your_config.json
```

画面左上角会显示：

```text
orange: 1/3
orange: 2/3
orange: CONFIRMED
```

需要调HSV或检查单帧原始结果时，临时绕过时间确认：

```bash
ros2 run cube_perception cube_detector \
  --source your_video.mp4 \
  --config your_config.json \
  --raw-detections
```

原则：调颜色时看raw；最终验收时不能带`--raw-detections`。

## 怎样保存并检查数字证据

```bash
ros2 run cube_perception cube_detector \
  --source your_video.mp4 \
  --config your_config.json \
  --jsonl result.jsonl \
  --output-video result.mp4 \
  --headless
```

每一帧的JSON中会有`tracking`：

```json
{
  "tracking": {
    "orange": {"streak": 3, "missed": 0, "confirmed": true}
  }
}
```

## 推荐调参顺序

1. 使用`--raw-detections`先把HSV和形状过滤调好；时间确认不能弥补持续误检。
2. 去掉`--raw-detections`，保持`confirm_frames=3`。
3. 正常移动相机，确认目标能稳定变成`CONFIRMED`。
4. 快速晃动一次；如果总是重新计数，适当调大`match_distance_px`。
5. 观察目标中心是否仍抖动；抖动明显就降低`smoothing_alpha`。
6. 在无目标视频中测试，不能出现持续`CONFIRMED`。
7. 修改ROS配置后重新编译相关包并重启节点。

## 验收标准

- 单个真实方块出现后，通常在3帧内确认；
- 单帧反光或短促色块不应发布为目标；
- 移走方块后，本帧起不再输出该目标；
- 正常移动时不会频繁从`CONFIRMED`掉回`1/3`；
- 确认后的位置跳动明显小于raw结果；
- 橙色和紫色独立计数，互不影响。

## ROI和轮廓过滤

连续帧确认只能处理短暂误检。持续存在的橙色背景也会被确认，因此原始检测前面又增加了两道门：

```text
ROI位置门 → 轮廓形状门 → 连续帧确认门
```

ROI使用0～1的画面比例：`roi_x_min_ratio`、`roi_x_max_ratio`、`roi_y_min_ratio`、`roi_y_max_ratio`。默认全画面，不在没见正式场地前写死。`vision_demo_roi.json`提供了当前桌面视频的示例起点。

轮廓过滤参数：

- `max_area_ratio`：拒绝占画面过大的同色背景；
- `min_rectangularity`：颜色轮廓填满最小旋转矩形的最低比例；
- `min_solidity`：拒绝锯齿、凹陷严重的轮廓；
- `min_side_px`：拒绝过细目标；
- `max_rotated_aspect_ratio`：拒绝过长色条，同时允许旋转后的方块。

离线预览会画出黄色ROI边框，并显示每种颜色的轮廓总数与通过数量。JSONL的`filtering`字段会记录small、large、shape和accepted计数。
