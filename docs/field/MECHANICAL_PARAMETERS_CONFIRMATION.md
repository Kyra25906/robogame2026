# RoboGame2026 机械机构与动作参数确认表

## 1. 这份表是做什么的

这份表请机械组填写，用来确认夹爪、升降机构和撤退动作在物理上应该怎样工作。

大白话说：软件不能只知道“抓一下”“升高一点”，还必须知道夹爪要张开多少、升到多高、允许差多少、最慢多久必须结束，以及停止后方块会不会掉下来。

专业上，这叫做冻结机构的**动作语义（action semantics）**、**物理参数（physical parameters）**、**允许范围（operating range）**、**安全极限（safety limit）**和**完成判据（completion criteria）**。

本表不要求机械组填写串口消息 ID、payload、CRC、字节序或十六进制样例；这些属于电控通信协议。机械组给出毫米、牛顿、秒和安全边界后，电控组再定义怎样编码，软件组再接入 ROS 2。

```text
机械组：动作在物理上应该怎样执行、怎样算完成、什么范围安全
电控组：怎样驱动电机、读取传感器、编码命令和反馈状态
软件组：怎样封装ROS 2接口、设置参数、超时和安全门控
```

## 2. 填写规则

每个数值参数尽量填写以下五项：

| 项目 | 大白话 | 专业含义 |
|---|---|---|
| 单位 | 这个数字按毫米、秒还是牛顿计算 | Unit |
| 推荐值 | 正常情况下建议使用多少 | Nominal value |
| 允许范围 | 在什么范围内可以正常工作 | Operating range |
| 安全极限 | 超过哪里可能损坏、掉落或碰撞 | Safety limit |
| 依据 | 来自设计图、计算还是现场实测 | Evidence/source |

如果目前不知道，请填写“未知，待实测”，不要凭感觉填写。

### 2.3 最小运动算例如何从清单产生

机械参数冻结后，我们至少建立以下运动算例。这里先定义“验证什么”，不会自动在真车上执行。

| 算例 | 使用的机械信息 | 我们能验证什么 |
|---|---|---|
| 空载夹爪开合 | M-02、M-04、M-16 | 方向、行程、速度和STOP是否正确 |
| 空载分段升降 | M-08至M-13、M-16 | 零点、层高、限位、重复精度和停止表现 |
| 标准抓取 | M-01至M-07、M-24 | 标准位置能否可靠夹住，完成判据是否有效 |
| 空夹 | M-06 | 系统是否会把夹爪闭合误报为抓取成功 |
| 小偏心抓取 | M-05、M-06 | 允许偏差内的捕获能力；不直接挑战安全极限 |
| 三层放置 | M-10、M-12、M-14、M-15、M-24 | 三层高度、释放过程和到位误差 |
| 动作中STOP | M-07、M-13、M-16、M-17、M-21 | 是否真正停止、是否下坠或掉落、能否安全恢复 |
| 撤退与稳定观察 | M-18至M-20、M-23 | 撤退是否避碰并解除相机遮挡 |
| 禁止并发动作 | M-22、M-23 | 软件互锁能否阻止危险动作组合 |

这些算例按以下层次执行：

```text
纸面评审
→ mock软件测试
→ 真车空载低速单动作
→ 真车带载单动作
→ 最后才允许完整任务
```

STOP、急停和失联安全没有通过前，不进入完整任务测试。

## 4. GRAB 抓取动作

### 4.1 大白话说明

## 5. LIFT 升降动作

## 6. RELEASE 释放动作

### 6.1 大白话说明

夹爪打开不一定代表方块已经掉到正确位置。需要说明张开多少、离放置面多高、打开后等多久，以及怎样判断方块没有粘在夹爪上。

### 6.2 专业定义

- 动作名称：`RELEASE`
- 动作语义：解除夹持，使方块与夹爪分离。
- 完成判据：**释放完成判据（release completion criterion）**。

## 7. STOP 停止动作

### 7.1 大白话说明

STOP不能只表示“不再发新命令”，而要说明机构多久能真正不动，抓着方块时会不会松手，升降机构会不会掉下来。
