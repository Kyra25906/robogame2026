# 现场待测清单（B2/B3）：哪些值是猜的、怎么测、错了会怎样

> 用途：现场每测一项就在「实测值」列填数，并把结果写回右侧「写回哪里」。
> 原则：**清单里所有数都是占位值（fake）**，不是结论。凡是依赖未标定里程计/航向的
> 段落，代码里已标 `evidence: estimated`；本清单把「estimated 具体指哪几个数」摊开。
>
> 更新：2026-09-17（B2 完成时）。相关设计见 `docs/field/GENERAL_FIELD_MAP_2026.md`、
> `ros2_ws/src/robogame_core/robogame_core/mission_route.py`。

## 0. 现场测试顺序（先做 A 类，A 类不通后面全是空转）

```text
A1 上电链路：STM32 → 树莓派 → /robot/status 50Hz → 急停 → 失联停车
A2 巡线读数：黑白基准实测 + 持久化            ← 不测则巡线永远走不起来
A3 里程计标度：命令 1.000m 量实际走了多少      ← 不测则所有距离判据都不可信
A4 停车点朝向：W01/W02/W04 的车头朝向
B1 巡线参数：kp/kd/vx_base/阈值（在真黑线上整定）
B2 路口签名：N02 拐角、N06 T 形路口各拍一段读数
B3 坡道：能否上/能否沿线/打滑
C1 取块：槽距、3 次抓取怎么移位
C2 搭建：2 层的摆法与放置高度
```

## B 类：阈值类（有值但都是猜的）

### B1 巡线（`robot.yaml` → `line_follow_controller`）

| 项目 | 占位值 | 怎么定 | 错了会怎样 |
|---|---|---|---|
| `kp` | `1.0` | 低速（vx_base 0.1）在直线上左右推车，看回正是否过冲 | 过小：蛇形跟不上；过大：振荡 |
| `kd` | `0.1` | 同上，抑制振荡 | 抖动 |
| `vx_base` | `0.2` | 逐步提到刚出现振荡再退一档 | 太快丢线 |
| `threshold` | `0.5` | 归一化后 0..1 的分界，看 ON_LINE 判定是否稳定 | 误判丢线/误判路口 |
| `edge_threshold` | `0.3` | 偏差超过它算压边 | 压边不响应 |
| `lost_threshold` | `5` | 连续几拍无黑才算丢线 | 太小：过坑误停；太大：冲出线才停 |
| `intersection_threshold` | `6` | **必须现场看路口签名**（B2 项） | 路口认不出 → 不转；认成丢线 → 误停 |

### B2 路口签名（决定「到路口了」这个判断本身）

| 项目 | 占位值 | 怎么测 | 错了会怎样 |
|---|---|---|---|
| N02（L 拐角，右转）期望状态 | `(INTERSECTION, ALL_BLACK)` | 手动推车/低速经过 N02，录 8 路原始值 | 不转（冲过拐角丢线）或提前转 |
| N06（T 路口，左转）期望状态 | 同上 | 同上 | 同上 |
| N03/N09/N06 直行通过 | 靠「路口计数」跳过（`passthrough_junctions: 1`） | 同上录一段，确认是几个「路口事件」 | 在 T 形路口误停/误转 |
| 线尽头（N10/N05）期望状态 | `(LOST,)` 连续 2 拍 | 沿线走到尽头录读数 | 与「意外丢线」混淆 → 该停不停/该走不走 |
| 路口稳定拍数 | 拐角 3 拍、线尽头 2 拍 | 按实测帧率折算时间（50Hz → 60ms/40ms） | 噪声误触发 |

### B3 坡道与运动参数

| 项目 | 占位值 | 怎么测 | 错了会怎样 |
|---|---|---|---|
| 巡线段限速 | `0.20`（起步段）/`0.25`（主路）/`0.15`（坡道/高台/返程） | 逐段提速，取「丢线前」的 80% | 冲过路口、下坡冲 |
| 坡道限速 / 角速度上限 | `0.15` / `0.30` | 坡上试走，看打滑与偏航 | 打滑跑偏、下坡加速 |
| 坡道判据（`ODOM_DISTANCE` 0.80） | 由实测坐标算出，但**依赖 A3 里程计标度** | 标定里程计后复算；必要时改用「离坡时间 + 里程」双判据 | 没走到坡顶就转段 / 冲过坡顶 |
| 平移距离（N05→W04） | 0.32 m | 卷尺复测 N05 与 W04 | 放置位错位 |
| 位姿容差 | 0.05 m / 0.087 rad（5°） | 按抓取/放置能容忍的偏差定 | 过严：永远到不了/反复重试；过松：压块 |
| 每段超时 `state_timeout_s` | `20.0`（`robot_field.yaml`） | 按实测每段最长耗时 ×2 | 过短：正常段被判超时；过长：卡住不报警 |

## D 类：每一段现场测试要留下的证据

每项测完记录：**命令、原始输出、实际数值、时间、结论（通过/不通过/证据不足）**。
归档到 `results/`（不进 Git），关键结论回填本清单与对应配置。

最低限度要留下：

1. `/robot/status` 与 `/pose` 的一段原始日志（证明链路与频率）；
2. 巡线 8 路黑白原始值（标定前后各一段）；
3. 里程计定距测试的「命令距离 vs 尺量距离」三组数据；
4. N02/N06/N10 的手推经过录像或读数序列（路口签名）；
5. 上坡/下坡各一次的成功或失败记录（含是否打滑）；
6. 一次「急停」单独录像（规则要求可单独证明，评分 5 分）。
