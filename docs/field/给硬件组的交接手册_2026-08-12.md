## 4. P0：MCU 回传帧的逐字节布局

**为什么缺这个就动不了**：当前代码能收到 MCU 的帧，但不知道帧里每个字节代表什么。不知道就不会解码，不解码就没有 `communication_ok`，没有 `communication_ok` 算法就拒绝一切动作。这是硬阻断。

### 4.1 STATUS 帧（类型 `0x12`）

**用途**：MCU 告诉上位机自己现在是什么状态——通信是否正常、急停是否触发、有没有故障。

|---:|---:|---|---|---|---|---|
| 0 | | | | | | |
| | | | | | | |
| | | | | | | |
| | | | | | | |
| | | | | | | |
| | | | | | | |
| | | | | | | |
| | | | | | | |

**至少需要包含**：

- 急停状态（是否被按下）
- IMU 状态（是否校准完成、数据是否有效）
- 机构故障标志（夹爪、升降、电机驱动是否有故障）
- 电池电压
- MCU 启动计数（boot_id，用于检测 MCU 是否重启过）
- 实体启动信号（比赛开关是否打开）

**填写示例**（仅供参考格式，实际值由你们定）：

```text

偏移 2 | 1 | u8  | flags   | 无 | 见位定义 | 0x00
  bit 0: emergency_stop
  bit 1: imu_calibrated
  bit 2: mechanism_fault
  ...
```

## 6. P0：错误码表

**为什么重要**：算法需要根据错误码决定"重试"、"跳过"还是"停车"。如果只返回"成功/失败"，算法不知道该怎么办。

| 错误码 | 含义 | 发生在哪个机构 | 算法应该怎么处理 | 硬件能自动恢复吗 |
|---:|---|---|---|---|
| 0 | 成功 | — | 继续 | — |
| 2001 | 协议未冻结（占位） | 全部 | 拒绝 | — |
| | | | | |
| | | | | |
| | | | | |

**建议至少区分**：

- 通信类错误（可重试）
- 机械类错误（不能重试，可能损坏）
- 传感器类错误（数据不可信）
- 超时类错误（可能卡住了）
- 安全类错误（急停触发、看门狗复位）

## 9. P1：现场联调安全顺序

不要一来就跑完整任务。按这个顺序逐级验收，前一步不过不进下一步：

```
1. 断电只连通信 → 确认帧格式、CRC、序号正确
2. 架空轮子 → 分别测试 +vx/-vx/+vy/-vy/+wz/-wz 方向
3. 超时停车 → 持续发低速命令后拔串口，确认 MCU 自己停车
4. 急停测试 → 低速运动中按急停，确认立即停止
5. 里程计+IMU → 推车对单位、方向、频率
6. 单机构空载 → 夹爪/升降单独测试，底盘不动
7. 机构带载 → 真方块测试抓到/没抓到/掉块/超时
8. 软件安全联锁 → 断通信/发故障检查算法是否拒绝
9. 最后才跑联合闭环
```

## 附录：快速参考卡片

### 当前串口帧格式（已冻结）

```
AA 55 | version:u8 | type:u8 | seq:u16 | len:u16 | payload[...] | crc16:u16
```

- 字节序：小端
- CRC：CRC-16/CCITT-FALSE，多项式 0x1021，初值 0xFFFF
- 最大载荷：512 字节

### 已分配消息类型

| 类型 | 方向 | 用途 | 载荷状态 |
|---|---|---|---|
| `0x01` | 上位→MCU | 速度命令 | **已冻结** |
| `0x02` | 上位→MCU | 机构命令 | **待协议** |
| `0x10` | MCU→上位 | 里程计 | **待协议** |
| `0x11` | MCU→上位 | IMU | **待协议** |
| `0x12` | MCU→上位 | 机器人状态 | **待协议** |
| `0x13` | 双向 | ACK/握手 | **已冻结** |

### 最重要的三件事（如果只能填三项）

1. **STATUS 帧的字节布局**（第 4.1 节）——没有它，算法永远拒绝动作
2. **机构完成/失败判据**（第 5.2 节）——没有它，不知道动作做完没有
3. **速度正方向和限幅**（第 7.1 节）——没有它，车不知道往哪走
