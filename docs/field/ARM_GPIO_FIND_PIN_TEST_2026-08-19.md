# 用「点灯测试」找出舵机信号针（2026-08-19）

## 背景与目的

`docs/field/MECHANISM_0x20_INTERFACE_ALIGNMENT_2026-08-18.md` §6.2 已冻结固件侧的五个舵机信号脚：

| 关节 | GPIO |
|---|---|
| 腰（基座） | PA2 |
| 肩（臂底 80KG） | PA3 |
| 肘 | PI7 |
| 腕 | PD14 |
| 爪 | PD15 |

**缺口**：这块板是 `STM32F427IIH6 / UFBGA176 / board=custom`
（见 `Four_Motor_PID_Test_1/Four_Motor_PID_Test/Four_Motor_PID_Test.ioc` 第 25、291 行），
仓库里没有它的原理图/PCB，**"这五个 GPIO 引到板上哪个物理针"没有任何文档**。
UFBGA176 是球栅阵列、芯片上无引脚可量，所以也不能靠"从芯片量到排针"解决。

**本方法**：让固件只驱动其中**一个** GPIO 输出 0.5 秒高 / 0.5 秒低的方波，
用万用表在板子上逐个针找"哪个针在 0V ↔ 3.3V 之间一秒跳一次"。
找到就是它。反过来也能验证已知的针（例如肩已接的 PA3）。

**为什么强调"一次只点一个脚"**：如果有两个脚同时跳，万用表分不清哪个是哪个；
一次一个，结果唯一、可复现。

---

## 一、动代码之前必须做的三件事

1. **拔掉舵机信号线。** 把已接的信号线（含已接好的肩）从板子上拔下来。
   原因：信号线拔掉后舵机完全断电控，这五个脚就纯粹是我们的测试点，
   误触也不会让机械臂动。**不拔线就烧测试固件 = 让 80KG 关节随机抽动，危险。**
2. **舵机动力电源也可以先断电。** 测的是 GPIO 的 0/3.3V，不需要舵机有电。
   但要保证**共地还在**：万用表量电压必须有共同参考地。
   → 上电前先用通断档确认「舵机/电池地 ↔ STM32 GND」是通的。
3. **STM32 单独上电**（USB 或控制电），不要给电机、不要按 PB2 授权、遥控器别碰。

## 二、代码改动（两处 + 一个新文件）

### 新文件

- `Four_Motor_PID_Test_1/Four_Motor_PID_Test/Core/Inc/arm_gpio_test.h`
- `Four_Motor_PID_Test_1/Four_Motor_PID_Test/Core/Src/arm_gpio_test.c`

Keil 工程 `IncludePath` 已含 `../Core/Inc`（`.uvprojx` 第 343 行）。
若把 .c 加进 `Application/User/Core` 组，Keil 会自动找到头文件；若不加组，
就按下面「做法 B」直接把函数贴进 main.c（**最简单，不碰工程结构**）。

### `main.c` 改动 1：把 `Arm_Init()` 注释掉

```c
  Remote_Init();
  Arm_Init();          /* ← 找到这行，注释掉。理由：它会启动 TIM7 伺服 PWM， */
                       /*   在后台不停翻转这五个脚，和测试方波打架。        */
  LineSensor_Init();
```

### `main.c` 改动 2：主循环里加一行

```c
    Remote_Update();
    RPI_Update();
    Arm_Update();                    /* 改动 1 已注释 Arm_Init()，这里不会输出 PWM */
    LineSensor_Update();

    ArmGpioTest_Update(HAL_GetTick());   /* ← 新增这一行 */
```

### `ARM_GPIO_TEST_MODE` 的取值

```c
#define ARM_GPIO_TEST_MODE   1   /* 0 = 关闭（默认，绝对安全）        */
                                 /* 1 = 找腰  目标 PA2                */
                                 /* 2 = 找肩  目标 PA3（可验证已知线）*/
                                 /* 3 = 找肘  目标 PI7                */
                                 /* 4 = 找腕  目标 PD14               */
                                 /* 5 = 找爪  目标 PD15               */
```

## 三、操作流程（每个脚约 1 分钟）

对 `MODE = 1..5` 重复：

1. 改 `ARM_GPIO_TEST_MODE`。
2. Keil 里 **Rebuild**（不是 Build，避免旧对象文件没更新）。
3. 下载到板子，复位运行。
4. 万用表拨 **直流电压 20V 档**，黑表笔接 **STM32 的 GND**，
   红表笔**逐个碰板子上每个可疑的针**。
5. 找到那个**在 0V 和 3.3V 之间约每秒跳一次**的针 → 记下它的丝印/位置。
6. 填表（下面），继续下一个 MODE。

### 记录表（现场填写）

| MODE | 目标 GPIO | 实测跳变的物理位置（丝印/第几排第几针） | 备注 |
|---|---|---|---|
| 1 | PA2 腰 | | |
| 2 | PA3 肩 | | 可与电控已接的线对照 |
| 3 | PI7 肘 | | |
| 4 | PD14 腕 | | |
| 5 | PD15 爪 | | |

### 判读要点

- **0V ↔ 3.3V 之间一秒一次跳** = 就是它。
- **恒定 3.3V 或恒定 0V** = 不是它（可能是 VCC/GND 针、上拉脚、或其它功能脚）。
- **在抖但没规律** = 可能是串口/复用脚，**不要选**。
- 万用表有些档位刷新慢，看到 5 秒内规律变化即可；不必苛求精确 1Hz。

---

## 四、测完之后必须做的事

1. `#define ARM_GPIO_TEST_MODE` 改回 **0**。
2. **恢复** `Arm_Init();` 那一行。
3. 删掉主循环里的 `ArmGpioTest_Update(...)`。
4. Rebuild + 烧回正常固件，确认上电后五个舵机信号脚**不输出**（`arm_servos_enabled == 0`）。
5. 把上面那张记录表填进
   `docs/field/MECHANISM_0x20_INTERFACE_ALIGNMENT_2026-08-18.md` §6.2，
   把"引脚定义"升级成"**引脚 + 板端物理位置**"，后续接线/排查不用再猜。

---

## 五、安全边界（能证明 / 不能证明）

**能证明**
- 测试固件确实在驱动 `arm.c` 里那五个 GPIO 之一（与伺服代码同一份 `arm_port`/`arm_pin` 表，
  不存在"测试用一套、生产用另一套"的偏差）。
- `Arm_Init()` 注释后 TIM7 不再输出伺服脉宽，测试方波不会被后台翻转覆盖。

**不能证明**
- 记录表里"物理位置"的正确性依赖现场读数，本方法**不能自动校验**；
  建议对 MODE=2（PA3 肩）与电控已接的线交叉验证一次，一致才说明读法可信。
- 不能证明舵机本身、供电、共地、机械行程是否正常——那是接线完成后的下一步。
- 本方法**不验证**脉宽/角度映射（`ARM_JOINT_PULSE_MIN/MAX`），只找物理针。

## 六、为什么不用「量通断找相邻针」这类捷径

坏主意：直接量 PA2 与 PA3 排针通断。STM32 的 GPIO 在复位后是**高阻输入**，
两个空脚之间本来就不导通；能测出的只有 ESD 保护二极管，读数随表笔档位和板子变化，
不可复现。**点灯法是唯一"结果由固件保证"的做法**，所以选它。
