# 上电后无人干预自主完赛：操作流程与检查点

> 目的：把「上电 → 小车自己跑完 6 分钟」这件事写成**可执行、可检查、可停止**的流程。
> 配套代码：`hardware.launch.py`（整栈）、`mission_manager`（路线执行）、
> `line_follow_controller`（巡线/转弯/坡道）、网页面板（观察与标定）。
>
> ⚠️ 本文是**操作约定**，不是验收结论。文末「尚未验证清单」里的每一项都还没有
> 真车证据；把它们当成「应该能用」，不要当成「已经能用」。

---

## 一、赛前一次性准备（不做完，上电自主不可能）

| # | 项目 | 怎么做 | 判据 |
|---|---|---|---|
| 1 | **巡线黑白标定**（阻断项） | 网页「状态与巡线」→ 按住标定白底 2 s → 按住标定黑线 2 s → 「应用标定」 | 面板显示「已生效并落盘」，且给出保存路径；节点状态里 `calibration_status` 显示可用 |
| 2 | **里程计标定** | 网页「里程计标定（尺量对照）」跑 3 组 0.50 m / 0.05 m·s⁻¹ 并填尺量 | 面板给出标度中位数与波动；波动 ≤3% 才算可用 |
| 3 | **停车点朝向** | 车放在 W01/W02/W04，对准目标后读 `/pose` 的 yaw | 填回 `field_layout.yaml` 的 `survey.stops` |
| 4 | **放置高度与摆法一致** | 面板会把不一致直接显示在「全流程路线」下的提示里 | 计划 2 层（`2+1`）要求 `place_heights_m` 前 3 项为 `[0.10, 0.10, 0.20]` |
| 5 | **限速天花板** | `robot.yaml` → `line_follow_controller.vx_base` | 生效限速 = min(本段限速, `vx_base`)；要让主路 0.25 生效，`vx_base` 必须 ≥0.25 |
| 6 | 参数版本 | 记录本机 `robot.yaml` / `robot_field.yaml` / `field_layout.yaml` 的 git SHA | 出问题时可复现 |

## 二、上电顺序（约 30 秒内完成，之后不应再有人碰车）

```text
1. 车放回启动区（车体中心投影完全在黑框内，规则 3.2.5）
2. 开电池 → STM32 上电 → 树莓派上电
3. 树莓派上启动整栈：ros2 launch robogame_bringup hardware.launch.py
   （或用 systemd 自启，见第三节）
4. 另开一个 SSH 窗口看网页：python3 tools/field_dashboard.py --calibration-file ~/robogame_line_calibration.json
5. 网页检查（下一节），确认后**所有人退到场地外**
6. 裁判系统给出开赛信号 → STM32 上报 physical_start → 任务自动开始
```

**上电后不会动**：任务状态机停在 `WAIT_FOR_PHYSICAL_START`，只有收到下位机的开赛
信号（`STATUS_PHYSICAL_START`）才会进入路线执行；在此之前即使巡线节点看到线也不会
动——它要的底盘授权由任务层给（`require_authorization: true`）。
这条是**设计约定**且被测试覆盖（`tests/test_mission.py`、`tests/test_mission_route.py`）。

## 三、可选：树莓派开机自启（减少一次人工输入）

用 systemd 让整栈随系统启动（**不会**让车在开赛信号前移动，原因同上）：

```ini
# /etc/systemd/system/robogame-bringup.service
[Unit]
Description=RoboGame bringup (autonomous match stack)
After=network.target

[Service]
Type=simple
User=pi
WorkingDirectory=/home/pi/robogame_algorithm
ExecStart=/bin/bash -lc 'source /opt/ros/jazzy/setup.bash && source install/setup.bash && ros2 launch robogame_bringup hardware.launch.py'
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

启用：`sudo systemctl enable --now robogame-bringup`；查看日志：`journalctl -u robogame-bringup -f`。
**注意**：自启前必须先完成第一节的标定落盘，否则节点会以「未标定」状态启动并大声报警。

## 四、上电后只看这一页：网页检查点

| 面板 | 应该看到 | 不对时说明 |
|---|---|---|
| 安全总览 | 通信正常 / 物理授权「未授权」（开赛前）/ 急停未触发 / 机构正常 | 通信异常 → 查串口；机构故障 → 不要开赛 |
| 状态与巡线 | 8 路读数在动、`state=ON_LINE`、`calibration_status` 显示标定可用 | 读数不动 → 探头/供电；标定不可用 → 回去标定 |
| 全流程路线 | 第一行显示「第 0/13 段 …」+「坡道正常」+「本段限速」+「第 k/5 步」 | 页面显示「任务层未上报」→ mission_manager 没在跑路线模式 |
| 里程计标定 | 标度已记录、波动 ≤3% | 没有数据 → 里程计判据全都不可信 |

## 五、无人干预期间

**唯一允许的人工动作是急停**（规则 4.2.4 S3）。除此之外：

- 不要进场地、不要扶车、不要拿方块（规则 3.2.1 S1/S3 判罚）；
- 不要用遥控器（会触发失联停车语义）；
- 不要点网页上的手动接管/巡线启动（会改变底盘授权来源）。

**内部已经做了的自我保护**（都是「宁可停下，不乱走」）：

- 巡线读数过期 → 节点停车，且段不推进；
- 路口转弯失败 → **保持零速不回退巡线**（方向没转对时继续往前开是危险的）；
- 坡道打滑卡住 → 停车并按失败重试本段；
- 段失败重试次数用尽 → 按**降级阶梯**处理（见下），面板会显示「⚠️ 已降级 N 次」；
- 急停/通信丢失/机构故障 → 优先级高于一切授权。

### 降级阶梯（重试耗尽之后）

| 失败的段 | 判据 | 动作 | 面板上会看到 |
|---|---|---|---|
| 巡线 / 坡道 / 路口转向 / 车体微移 | 位置或朝向不可信 | **安全停车**并释放授权 | 状态 FAILED，`detail` 里写明「安全停车」 |
| 取块（框里已有 ≥1 块） | 位置可信、有存货 | 跳过剩余取块，直接去搭建 | 「已降级 1 次」，当前段变成搭建段 |
| 取块（一块都没抓到） | 位置可信、没货 | 退到撤退位安全收场 | 「已降级 1 次」，当前段变成撤退段 |
| 放置失败 | 位置可信 | 退开，不挡搭建区 | 同上 |

含义要说清：**降级不会把失败变成成功**，它只保证失败之后车**收场得体**
（退开或停下），并且把「已经拿到的分」（已抓/已放的块）保住。
策略可关：`robot_field.yaml` → `mission_manager.degrade_on_failure: false`
（关掉就回到「一失败即判死」，便于现场对照排查）。

## 六、异常与恢复

| 现象 | 处理 |
|---|---|
| 车停在半路不动，网页「状态」为 FAILED | 看「状态」里的 `detail` 与 `/mission/route` 的 `route_error`；**不要**手动续跑，按异常处理流程（规则 3.2.3） |
| 急停后想继续 | 复位急停 → 任务状态机在 `SAFE_STOP` 是终态，需要重启节点重新走一遍自检（当前**不支持热恢复**） |
| 网页连不上 | 车可能仍在跑；不要靠页面残留值判断。看日志 `journalctl` 或 SSH |
| 巡线标定丢失（重启后 `calibration_status` 不可用） | 说明上次没落盘成功；重新标定并确认面板给出保存路径 |

## 七、尚未验证清单（**不要当成已验收**）

1. 真车上的巡线参数（kp/kd/vx_base/阈值）——全部是占位值；
2. 路口签名波形（N02/N06）、转弯角速度 0.6 rad/s、最短转向时间比例；
3. 坡道 14° 的限速与打滑阈值、上下坡能否沿线；
4. 槽距 0.15 m 与侧移方向（「正侧移 = 车的右侧」是约定，现场必须核对）；
5. 放置高度与摆法（`[0.10,0.20,0.30]` 与 2 层计划的冲突尚未拍板）；
6. 里程计标度（面板已就绪，数据未采）；
7. **任何节点的运行时行为**：开发机上没有 rclpy，所有接线只有 AST 结构断言与
   纯逻辑测试作证——`colcon build` 后第一次真跑才算验证。
