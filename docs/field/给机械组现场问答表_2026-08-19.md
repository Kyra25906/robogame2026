### 设计约束与动作语义

| # | 机械组确认 | 对软件的含义 |
|---|---|---|
| C-1 | **机械臂没有任何反馈，只能单侧下命令** | 完成判据只能是「时间到/超时」，成功证据只能靠相机复核；软件只能重试，不能修正末端精度。与 `MECHANISM_0x20_INTERFACE_ALIGNMENT_2026-08-18.md` 锁定结论一致 |
| C-2 | **GRAB 只用下「抓取」命令，不用具体爪开合毫米数** | 软件不下发开合宽度（protocol GRAB parameter=0，已冻结），**软件不需要张开宽度/闭合缝隙两个数**（爪自开合，机械自检即可）；唯一相关派生数字是「抓取容差窗口」（张开宽度−方块尺寸+EVA 压缩），**上车实测**（放方块偏一点试抓）而非机械给数 |
| C-3 | **目前没有升降装置** | 真车模式**禁用 LIFT**；任务改为**单层地面放置**；三层高度参数暂缓冻结 |
| C-4 | **车走的时候爪子不要动，或收回安全位置** | 软件互锁：底盘运动期间禁止机构动作；需要「安全收回姿态」参数 |
| C-5 | **抓取的时候底盘要保持静止** | 软件互锁：GRAB 前底盘速度必须为 0 |
| C-6 | **底盘只能前后 + 原地转；左右平移偏差过大不可用** | 软件**禁止输出横移 VY**（恒 0）；导航与视觉对准从「横移纠偏」改为「转向对准 + 直线接近」 |
| C-7 | **抓取在车右侧方向；云盘旋转约 90° 放入车尾框；从车尾框取出后在车尾搭建；云盘旋转在车的右侧进行，尽量不要转到左侧** | 「取出→存入车尾框」和「从车尾框取出→搭建」是**两个物理动作**，任务状态机需新增入库/出库状态（对应最小请求单 Q10 的答复）；云盘工作区间为「右侧 ↔ 车尾」约 90° 弧，避开左侧 |

| C-10 | **云盘可转 360°，但实际用不到那么多** | ARM_SET 云盘关节值域按 360° 设计，软件只允许在工作区间（右侧↔车尾约 90° 弧）内下发，越界拒绝 |
| C-11 | **肩 / 肘 / 腕角度范围待确认** | 与电控一起冻结三个（加肘后四个）关节的角度映射后才发真实 ARM_SET |
| C-12 | **相机打算装到能看见搭建区、材料区的位置（具体待上车确认）** | 外参（高度/俯仰/遮挡）仍待上车标定；安装位置需覆盖车右侧抓取位 + 车尾搭建区 |
| C-13 | **臂长：肩关节→手腕 270mm（爪在腕端，实际末端更远）；后期计划改 150mm+150mm 两段（加肘）** | 当前单段臂最大伸展 270mm（肩→腕）；改两段后直线伸展最大 300mm、随肘弯曲减小。已确认：**现 270mm 实际能够到车尾框** |
| C-14 | **云盘、肩、腕（未来加肘）各有独立电机；云盘装在车中心附近** | 3 DOF（云盘/肩/腕），加肘后 4 DOF；云盘中心 ≈ 车中心 → 到车尾约 237mm，270mm 肩→腕 + 爪长可覆盖车尾框（已确认够到） |
| C-15 | **释放时方块有粘连风险**（EVA 轻软，可能被爪带起/粘住） | RELEASE 不能以「爪打开」为完成判据，需防粘连：释放停留时间/释放高度/视觉复核方块已离开；入库车尾框同样适用 |
| C-16 | **无防粘连机构；爪「释放」动作即大角度张开，应能保证不粘（「应该」待实测）** | RELEASE = 释放命令（大角度张开）+ 停留时间 + 相机复核；「应能保证」是机械估计，软件仍按「相机确认方块已离开」为准，不能依赖猜测 |
| C-17 | **抓取/释放动作耗时暂无法给出：机械臂目前是遥控手动控制，自动控制下的耗时不好说** | 软件用**保守可配置临时超时**（不据此宣布真车通过）；等电控 arm.c 自动指令通道就绪后实测标定。自动通道是否就绪是下一步的关键依赖 |
| C-18 | **云盘可转向任意角度（含朝前），只需下命令旋转到目标角度** | **D-4 判据①（行驶时臂朝前）✓ 确认**；「尽量不转左侧」降级为操作摆动偏好（入库/搭建摆动仍走右侧弧），非能力限制。注意：云盘转向能力 ≠ 前向抓取动作（D-1 前抓仍为未来，抓取姿势依赖肩/腕/爪几何） |
| S-1 | **相机方案建议（未验证）：前向对准 + 原地转 90° + 开环抓取** | 对准阶段材料区在正前方（前向相机，现有逻辑）→ 原地转 90°（WZ 闭环，材料区转到右侧）→ 已知偏移开环抓取。相机只需前向可见材料区 + 巡线。**待上车验证**：① 转后方块离车中心 ≤ 云台右侧可达（270mm+爪长）② 相机最近对焦距离/视野是否覆盖该站位 ③ 转 90° 定位误差能否把方块留在捕获窗口内。车尾搭建的放置验证（后视 / 转车回头 / 计时兜底）待设计稿定 |
| S-2 | **转车精度是 S-1 的命门，必须实测**：IMU 可能无效（`imu_valid=false`）、轮式里程计有打滑风险（横移差即打滑证据）、AprilTag 不一定覆盖材料区 | **现场测试：原地转 90°，量实际角度**。±2° → S-1 成立；±10° → S-1 作废。不能假设转得准 |
| S-3 | **对角线逼近（S-1 作废时的首选替代，零新硬件）**：把爪的右侧抓取点标定成相机画面里的固定像素点，车直接开让方块"走到"该点，停住即抓 | 视觉闭环，不依赖转向精度。**前提：抓取点在前向相机视野内**。几何账：抓取点离车中心 270mm、相机在车头约 237mm → 夹角 ≈49°，**普通 60~90° 相机看不到，需 ≥100~120°（广角）或固定偏转安装，或抓取姿势前倾（待 C-11）**。判据=拍照看 ☆ 在不在画面 |
| S-4 | **广角相机评估（未验证）**：可解决"抓取点不在视野"，但有四类问题——① 边缘畸变砸中抓取点（`perception.py:63` 是线性模型，边缘不准）② 每度像素减半、对准精度变粗 ③ 边缘透视使宽高比过滤失真（`perception.py:43`）+ 车体/臂自身入画（ISSUE-002）④ 换相机=重标定+重调 HSV+重跑性能测试+近距对焦验证 | **验证路径（先测后买）**：上车拍一张"方块在抓取点"的照片跑现有检测器：看不见→广角有必要；边缘糊/歪→标定畸变+undistort 或调安装角度让抓取点居中；误差大→实测抓取点 lateral 误差是否可用 |
| S-5 | **单相机伺候三位置的唯一路径 = 相机永远只看前方**：① 巡线→红外传感器阵列（计划内硬件），相机解放 ② 右侧抓取→S-1 或 S-3（相机无需看右侧）③ 车尾搭建验证→放完转车 180° 回头确认（验证不需抓取级精度，转车误差可接受） | 相机云台与 eye-in-hand 都死在「无反馈」（C-1）上，本方案是唯一与无反馈兼容的路线；相机装好不动，省云台/广角。**朝前的理由**：相机剩下的活（前向对准/标签矫正/回头验证）都发生在「车头指向目标」的时刻——任务总是鼻朝前开向目标；装侧/装后会同时废掉对准和回头验证。巡线归红外后，相机专注对准+矫正，可调高安装位和俯仰角（C-12 待上车定）。**修正**：S-3 的"抓取点在视野"前提**不成立**于普通前向安装（几何夹角 ≈49°，需 ≥100~120° 视场或偏转安装或抓取姿势前倾）——"90° 中等视角可兼得"说法作废 |
| D-2 | **相机云台（水平舵机云台，修正结论）**：可重复机构（舵机/步进，约 ¥10~20，直连树莓派 GPIO、**不动 STM32 固件**）下，误差预算优于底盘转（δ₁≈±1° vs δ₂≈±2~5°，且对准全程视觉闭环、车尾验证免转车）——**"相机开环转+对准"确实更优（数学上）** | **但更优≠值得**：成本=新机构+碰撞（云台可能挡臂的 90° 摆动路径）+振动+一次性坐标标定+新故障面。**决策顺序**：先 S-2 实测底盘转 90° 误差 + 拍照看固定相机能否覆盖抓取点 → 转得准→S-1/S-3 零硬件；转不准+看得见→S-3；**转不准+看不见→舵机云台才是正确选择（比广角干净）**。修正：之前写"前提=角度反馈，没有就免谈"是错的——前提是**可重复机构**，不是编码器反馈 |
| D-3 | **眼在手（eye-in-hand，腕部相机 + 视觉伺服）**：指令近似位置即可支撑（P-1 可重复性原则：臂关节可重复→腕相机位姿近似已知→手眼标定吸收系统偏差→伺服闭环走视觉不走臂编码器），抓取对准精度最高 | **四道关**：① 臂自动通道未就绪（C-17，硬阻塞）② 第二相机，推翻"单相机+阶段互斥"既定决定 ③ 走线穿过旋转云盘（滑环/软线）④ 预定位交接（前向相机先粗对准进腕相机视野）。负载下垂会劣化开环动作精度（闭环不受影响）。**定位**：未来臂自动化后的选项，不是现在 |
| P-1 | **设计原则：误差预算（error budget）**——开环可用的判据是「开环节误差加总 < 容差窗口」，不是「有无闭环」 | ① **测量链路上的开环节会把误差×距离放大**（1° ≈ 250mm 处 4.4mm），且测量错=软件自信地错，比动作错更糟——云台/眼在手因此不可用 ② **可重复（步进/硬限位/编码器）可用一次性标定吸收，不可重复才"一定不行"** ③ **闭环可以放别处**：S-3 把视觉闭环放在车上，臂只贡献固定可标定的姿态误差——本项目整体并非开环，只是闭环放对了位置 ④ S-1 转车 90° 是开环节，误差必须实测后计入预算 |
