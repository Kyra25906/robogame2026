# 两人算法最终分工

## 我们这一侧：

负责：

- `cube_perception`：真实照片、视频、摄像头、HSV、ROI、轮廓过滤和连续帧确认。
- `motion_control`：接近减速参数、加速度限制、安全停止和结果管理。
- `manipulator_client`：视觉对准、抓取、放置、超时和机构服务调用。
- `mission_manager`：单块闭环、多块顺序、有限重试和安全降级。
- `robot_bridge` 软件部分：串口帧、状态解析、机构命令和真实模式保护。
- `robogame_interfaces`：统一消息、服务、错误码和单位。
- `robogame_bringup`：启动文件、YAML参数、模拟/硬件切换。
- 自动测试、同步脚本、使用说明、演示流程和整车集成。

近期优先级：

1. 完成真实摄像头视觉验收。
2. 运动控制速度变化限制和可调减速半径已完成软件实现，下一步在Ubuntu模拟并等待真车标定参数。
3. 根据电控回复实现真实协议，不提前猜载荷。
4. 完善抓取结果验证和掉块后的安全行为。
5. 保证单块任务闭环优先于三块策略。

## 巡线（Line following）分工（2026-08-17 补充）

结论：**巡线 = 上位机决策与控制**，不放下位机实现；下位机只负责八路灰度传感器采集与上送。

- **算法一**：巡线上位机集成——把巡线作为「路段类型」接入 `motion_control` / `mission_manager` 路线选择（路段链、模式切换、与路点/视觉对准的仲裁）；「巡线遥测」协议字段的字节布局冻结与实现（与电控共同确认）。
- **第二位算法同学**：`robogame_core/line_follow.py` 纯算法模块（八路灰度原始值 → 横向偏差 + 纠偏输出 + `ON_LINE/LEFT/RIGHT/LOST` 传感器状态机）与 `tests/test_line_follow.py` 单元测试；灰度阈值标定流程；场地黑线位置测量；八路模块是否装车、接口电平、ADC 通道的电控确认。
- **共同确认**：任何坐标、单位、消息字段和安全行为变更（含巡线遥测字段）先共同确认；真车贴线联调时按「一人操作观察急停、另一人运行记录」执行。
- 边界：第二位同学不写 ROS 节点、不改 `motion_control/node.py`/`mission_manager`/`robot_bridge`、不碰串口协议实现；算法一不做灰度标定与场地黑线测量。
