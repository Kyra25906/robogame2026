### 「遥控下不准」意味着什么：闭环能补的和不能补的

遥控是**开环**的——人眼估计距离、手动打杆、没有任何反馈。自动是**闭环**的——里程计 + IMU + 视觉对准 + 红外巡线持续纠偏。
**遥控下不准，是开环的必然结果，不是自动模式也会不准的证据。** 但要逐项分清楚，不能笼统乐观：

| 遥控下的「不准」表现 | 根因 | 自动模式能否补 | 靠什么补 |
|---|---|---|---|
| 走不直、往一边偏 | 四轮转速不匹配 / 开环无反馈 | ✅ **能，且这正是闭环的强项** | 里程计 + IMU 航向闭环；红外巡线横向纠偏 |
| 停车冲过头 | 无减速规划 + 人的反应延迟 | ✅ **能** | `motion_control` 已有减速半径与加速度限制（软件已实现，待标定） |
| 横移时带着旋转 / 方向偏 | 麦轮解算常数或轮序方向有偏差 | ✅ **大部分能** | E3 落地低速标定（直行 1m / 横移 1m / 旋转 360° 各 10 次）求出补偿系数 |
| 长距离后位置越来越偏 | 积分漂移 | ✅ **能** | AprilTag 绝对矫正 + 巡线横向约束 |
| 停到方块前的位置每次不一样 | 开环定位 | ✅ **能** | 视觉对准（`manipulator_client` 已实现对准逻辑）——不依赖底盘停得准，靠视觉最后一步收敛 |
| 夹爪有时夹不住 / 夹取位置飘 | 机械回差、无位置反馈 | ⚠️ **只能重试，不能修正** | 抓取结果验证 + 有限重试（G3.1）；根治要机械 |
| 升降停不到指定高度 | 无闭环位置反馈 | ❌ **补不了** | 需机械/电控给位置反馈；否则只能靠层高表实测标定 + 接受误差 |
| 放置后建筑歪 / 倒 | 机构末端精度 + 释放瞬间扰动 | ⚠️ **部分** | 降低层数（P2-4）、放置前视觉复核、释放后慢速撤离 |

**结论**：底盘一侧的「不准」几乎全部在算法可补范围内——这是算法真正能兜底的地方，而且我们已有的 `motion_control` / 视觉对准代码就是干这个的。**机构末端精度是补不了的那部分**，对策是降低对它的要求（少搭一层、多用视觉复核、失败就重试而不是硬上）。

**行动项**：请在遥控实测时按上表分类记录具体表现（哪种不准、偏多少、可复现吗），这直接决定 E3/E4 的标定重点。

### 划清边界：什么真的必须上车

一直被混为一谈的两类，此后分开处理：

- **必须上车（「量」与物理现象）**：焦距实测、现场光照下的 HSV、航点真实坐标、轮径与麦轮解算补偿系数、红外阈值整定、满载竞争下的 CPU 余量、串口抖动、打滑、遮挡、机构重复精度。

    | | 甲：红外 → 树莓派 GPIO | 乙：红外 → STM32 → 串口遥测 |
    |---|---|---|
    | 电控工作量 | 接线 + 确认电平 | 接线 +（模拟型）启用 `HAL_ADC_MODULE_ENABLED` + DMA 扫描 + 采样任务 + 新增协议消息 + 冻结字节布局 + **重新编译烧录** |

    | 接线 | 需从底盘拉线到树莓派 | ✅ 就近接 |
    | 延迟 | 一跳 | 10–20ms（0.2m/s 下约 4mm，**可忽略，不构成否决理由**） |

  - **待问电控的两句话**：①「限幅改动大概什么时候能烧录，巡线采集能不能一起做进去？」②「串口物理层是 USB CDC 还是 USB 转 UART？」

## 阶段 G：自动完赛能力（从「能跑一次」到「6 分钟拿满分」）

二审只要求录像里跑通一次；**完赛要求 6 分钟内连续、多轮、抗干扰、不崩**。这是两种不同的工程标准，G 阶段全部是二审之后仍必须做的。

### G1 任务循环与多目标（当前是硬阻塞）

- [ ] **G1.1 打破终态**：`COMPLETE` 现为永久终态（`mission.py:82-83`、`:137-140`），跑完一座塔就永久停机。规则是「最高 3 座、上不封顶」→ 改为可循环重入 `GO_TO_ORANGE`。
- [ ] **G1.2 多轮状态隔离**：每轮重入必须重置 `cargo`、`retries`、`entered_at`、视觉跟踪状态；确保上一轮残留不污染下一轮（易漏点）。
- [ ] **G1.3 已建成建筑登记**：记录已搭建塔的位置与层数，下一轮不重复选同一位置、不撞已有建筑。
- [ ] **G1.4 材料区目标去重**：已被取走的方块不再作为目标；多个同色候选时按「距离最近 + 姿态最正」而非仅最高置信度选择。

### G2 时间预算与策略（6 分钟怎么花）

- [ ] **G2.1 全局倒计时**：任务层引入赛时时钟，所有决策可查询「剩余多少秒」。
- [ ] **G2.2 单轮时间预算表**：实测一轮（取→运→放）耗时，据此算 6 分钟内现实可完成的轮数；对照 `docs/field/TIME_BUDGET.csv` 更新。
- [ ] **G2.3 放弃策略**：单个目标尝试超过阈值即放弃转下一个，不在一块方块上耗死。
- [ ] **G2.4 收尾策略**：剩余时间不足以完成一轮时，停止新取件，确保已搭建筑稳定且机器人脱离（保住已得分，避免撞塌自己的塔）。
- [ ] **G2.5 层数与座数权衡**：搭高（分高但风险大、重心问题）vs 搭多座（稳）——用实测成功率决定，不靠感觉。

- [ ] **G3.4 上坡打滑 / 卡住**：检测到位移停滞 → 退回重试 → 换角度上坡。
- [ ] **G3.5 视觉误检 / 无目标**：材料区搜不到目标时的扫描策略与超时。
- [ ] **G3.6 通信闪断**：区分「瞬时丢帧」与「真断线」，前者不应直接判死（与 A2 同源问题）。
