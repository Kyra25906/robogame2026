## 0.5 硬件依赖分级：算法能兜什么、兜不住什么

> 背景：电控与机械推进受阻，需明确算法的能力边界，避免把兜不住的事情当成能兜。
> **原则：安全门一律不绕过。** 不得为让车动而绕过 `Chassis_RpiLimitsReady()`、`RPI_IsReady()`、`physical_start`、150ms 看门狗或急停锁存（ISSUE-021 明令禁止）。绕过去是拆安全网，不是解决方案。

### 甲类：算法绝对兜不住（必须硬件交付，否则该项目 0 分）

| # | 依赖 | 阻塞分值 | 现状 | 最小交付 |
|---|---|---|---|---|
| **甲1** | **STM32 非零速度限幅**（ISSUE-021） | **60 分**（运动决策 20 + 取存镖 20 + 建筑搭建 20） | `chassis.h` 中 `CHASSIS_RPI_VX/VY/WZ_LIMIT_MPS` 全为 `0.0f`，固件结构性拒绝一切自动速度命令。**但遥控路径能动 → 硬件与解算是通的，这是授权门不是能力问题** | 填保守首值（建议 0.2 m/s 起）→ 重新编译烧录 → 架空复验。若遥控与 RPi 共用同一套 `Chassis_` 解算，轮径/轮序/方向无需重新冻结。**只能电控做** |
| **甲2** | 机构抓放的**重复精度** | 40 分（取存 20 + 搭建 20） | 遥控下机构能动，但末端位置不稳定；GRAB/RELEASE/HOME 已映射，冻结表实测参数未填 | 机械提高夹爪重复性 + 填冻结表实测值。**算法只能重试、不能修正末端精度**（见下表） |
| **甲3** | 相机物理安装 | 40 分（同上） | 外参从未标定，安装高度/俯仰/遮挡未知（ISSUE-002） | 装上、固定、量出高度与俯仰角 |
| **甲4** | 电控布线 / 形态完整 | 20 分 | 纯硬件评分项 | 理线、外观整理（录像前完成即可） |

**甲1 是全局第一优先级。** 在它解决前，阶段 E 之后的所有工作都无法验证，算法只能在模拟里空转。

> **2026-08-18 补充事实：遥控器下底盘与机械臂已能动，只是不准确。**
> 这把甲1、甲2 的性质都改变了——电机/驱动/接线/麦轮解算/机械结构全部是通的，`0.0f` 挡住的只是「树莓派自动路径」的授权门。甲1 大概率退化为「填三个常量 + 重新烧录」，因为遥控路径若共用同一套 `Chassis_` 解算，轮径/轮序/正方向已经被验证过了（需电控确认）。

### 「遥控下不准」意味着什么：闭环能补的和不能补的

遥控是**开环**的——人眼估计距离、手动打杆、没有任何反馈。自动是**闭环**的——里程计 + IMU + 视觉对准 + 红外巡线持续纠偏。
**遥控下不准，是开环的必然结果，不是自动模式也会不准的证据。** 但要逐项分清楚，不能笼统乐观：

| 遥控下的「不准」表现 | 根因 | 自动模式能否补 | 靠什么补 |
|---|---|---|---|
| 走不直、往一边偏 | 四轮转速不匹配 / 开环无反馈 | ✅ **能，且这正是闭环的强项** | 里程计 + IMU 航向闭环；红外巡线横向纠偏 |
| 停车冲过头 | 无减速规划 + 人的反应延迟 | ✅ **能** | `motion_control` 已有减速半径与加速度限制（软件已实现，待标定） |
| 横移时带着旋转 / 方向偏 | 麦轮解算常数或轮序方向有偏差 | ✅ **大部分能** | E3 落地低速标定（直行 1m / 横移 1m / 旋转 360° 各 10 次）求出补偿系数 |
| 长距离后位置越来越偏 | 积分漂移 | ✅ **能** | AprilTag 绝对矫正 + 巡线横向约束 |
| 停到方块前的位置每次不一样 | 开环定位 | ✅ **能** | 视觉对准（`manipulator_client` 已实现对准逻辑）——不依赖底盘停得准，靠视觉最后一步收敛 |
| 夹爪有时夹不住 / 夹取位置飘 | 机械回差、无位置反馈 | ⚠️ **只能重试，不能修正** | 抓取结果验证 + 有限重试（G3.1）；根治要机械 |
| 升降停不到指定高度 | 无闭环位置反馈 | ❌ **补不了** | 需机械/电控给位置反馈；否则只能靠层高表实测标定 + 接受误差 |
| 放置后建筑歪 / 倒 | 机构末端精度 + 释放瞬间扰动 | ⚠️ **部分** | 降低层数（P2-4）、放置前视觉复核、释放后慢速撤离 |

**结论**：底盘一侧的「不准」几乎全部在算法可补范围内——这是算法真正能兜底的地方，而且我们已有的 `motion_control` / 视觉对准代码就是干这个的。**机构末端精度是补不了的那部分**，对策是降低对它的要求（少搭一层、多用视觉复核、失败就重试而不是硬上）。

**行动项**：请在遥控实测时按上表分类记录具体表现（哪种不准、偏多少、可复现吗），这直接决定 E3/E4 的标定重点。

### 乙类：算法可以替代或大幅降低依赖（真正的兜底空间）

| # | 原计划依赖 | 算法替代方案 | 价值 |
|---|---|---|---|
| **乙1** | 八路灰度巡线走 STM32 ADC（`HAL_ADC_MODULE_ENABLED` 被注释禁用、遥测字节未冻结、需固件改动） | **红外巡线阵列直连树莓派 GPIO**：选带比较器输出的**数字型**红外模块（TCRT5000 类，板载电位器调阈值），直接读 GPIO，**不经 STM32、不改固件、不改串口协议** | 把巡线从「等电控开 ADC + 冻结协议 + 重新烧录」变成「接线 + 一个 ROS 节点」；第二位同学的 `line_follow.py` 纯算法（偏差→纠偏→状态机）**原样复用**，只换输入适配器 |
| **乙2** | 真实 IMU（`imu_valid=false`，pitch 从未接入） | 降级：yaw 仅用轮式里程计 + AprilTag 绝对矫正；坡道不做 pitch 补偿，改为**固定限速 + 打滑检测（里程计 vs 期望速度）** | 去掉对 IMU 标定的硬依赖，代价是精度下降 |
| **乙3** | STM32 真实编码器里程计（当前疑为命令速度积分） | AprilTag 绝对矫正可压制积分漂移；巡线提供横向约束 | 降低对里程计精度的依赖 |
| **乙4** | 第二个相机（机械可能给不出） | 单相机 + 阶段互斥：巡线段看地面、抓取段看方块、矫正时定点转向看标签 | 零新增硬件 |
| **乙5** | 视觉倒塌检测 | 短期用 3s 计时 + INCONCLUSIVE 诚实标注，不判死 | 不阻塞搭建得分 |

**乙1 是本次最重要的策略调整**：巡线传感器要补装（这个躲不掉），但**接哪儿**是可选的。接树莓派 GPIO 就绕开了「电控开 ADC + 冻结遥测字节 + 重新编译烧录」整条链路——电控组当前正卡在这条链路上。

### 结论：分层保底目标

| 场景 | 可得分 | 说明 |
|---|---|---|
| 甲1 不解决 | ≤ 25 分 | 只剩布线 10 + 形态 10 + 急停 5；车不能自主动。**这是唯一的灾难情形，必须避免** |

    - `gpiozero` / `lgpio` 读 8 路数字量；软件去抖（连续 N 帧一致才认）；发布 `/line/raw`（8 位布尔数组 + 时间戳）。
    - 采样率 ≥100Hz，与 `line_follow` 解耦；数据过期判断复用现有 staleness 模式。
    - **不引入新的安全旁路**：巡线只影响 `/cmd_vel` 的横向纠偏量，急停与看门狗链路完全不经过它。
  - **接口适配**：第二位同学的 `line_follow.py` 原设计输入是「八路灰度原始值」。数字型输入为 0/1，加权质心算法照常成立（权重×激活通道的加权平均）。**告知他输入量纲改为布尔数组，其余控制律与状态机不变，工作不作废。**
  - 单测：合成 8 位布尔序列（居中/左偏/右偏/全灭=LOST/全亮=交叉口/单点跳变=噪声）全部离线可做。
  - 现场依赖：模块装车位置（距地高度 5–10mm 是典型值）、电位器阈值整定、黑线实测位置（D3，第二位同学）。
- [ ] **C6 P2 稳健性**（穿插）：P2-1 边界收紧到本方半场（当前 `x∈[-0.2,7.4]` 允许进对方半场，规则 3.2.1 S4 越线要罚）；P2-2 `/cmd_vel` 三发布者仲裁；P2-4 层高上限与机械确认。

## 阶段 G：自动完赛能力（从「能跑一次」到「6 分钟拿满分」）

二审只要求录像里跑通一次；**完赛要求 6 分钟内连续、多轮、抗干扰、不崩**。这是两种不同的工程标准，G 阶段全部是二审之后仍必须做的。

### G1 任务循环与多目标（当前是硬阻塞）

- [ ] **G1.1 打破终态**：`COMPLETE` 现为永久终态（`mission.py:82-83`、`:137-140`），跑完一座塔就永久停机。规则是「最高 3 座、上不封顶」→ 改为可循环重入 `GO_TO_ORANGE`。
- [ ] **G1.2 多轮状态隔离**：每轮重入必须重置 `cargo`、`retries`、`entered_at`、视觉跟踪状态；确保上一轮残留不污染下一轮（易漏点）。
- [ ] **G1.3 已建成建筑登记**：记录已搭建塔的位置与层数，下一轮不重复选同一位置、不撞已有建筑。
- [ ] **G1.4 材料区目标去重**：已被取走的方块不再作为目标；多个同色候选时按「距离最近 + 姿态最正」而非仅最高置信度选择。

### G2 时间预算与策略（6 分钟怎么花）

- [ ] **G2.1 全局倒计时**：任务层引入赛时时钟，所有决策可查询「剩余多少秒」。
- [ ] **G2.2 单轮时间预算表**：实测一轮（取→运→放）耗时，据此算 6 分钟内现实可完成的轮数；对照 `docs/field/TIME_BUDGET.csv` 更新。
- [ ] **G2.3 放弃策略**：单个目标尝试超过阈值即放弃转下一个，不在一块方块上耗死。
- [ ] **G2.4 收尾策略**：剩余时间不足以完成一轮时，停止新取件，确保已搭建筑稳定且机器人脱离（保住已得分，避免撞塌自己的塔）。
- [ ] **G2.5 层数与座数权衡**：搭高（分高但风险大、重心问题）vs 搭多座（稳）——用实测成功率决定，不靠感觉。

### G3 容错与降级（任何单点失败都不能导致整场 0 分）

逐个失败模式定义「检测 → 重试 → 降级 → 兜底」四级响应：

- [ ] **G3.1 抓取失败 / 中途掉块**：重试上限、掉块后货物记账回滚、是否原地重找。
- [ ] **G3.2 巡线 LOST**：连续 N 帧丢线 → 减速搜索 → 回退到路点导航 → 仍失败则停车报告。
- [ ] **G3.3 标签长期不可见**：里程计漂移累积超阈值时的处置（降速、就近找标签、或接受降级精度）。
- [ ] **G3.4 上坡打滑 / 卡住**：检测到位移停滞 → 退回重试 → 换角度上坡。
- [ ] **G3.5 视觉误检 / 无目标**：材料区搜不到目标时的扫描策略与超时。
- [ ] **G3.6 通信闪断**：区分「瞬时丢帧」与「真断线」，前者不应直接判死（与 A2 同源问题）。
- [ ] **G3.7 建筑倒塌**：检测到自己搭的塔倒了 → 是否重搭、还是转下一座。
- [ ] **G3.8 兜底原则**：任何未预期异常 → 安全停车而非乱动；急停始终最高优先级。
