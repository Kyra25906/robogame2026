# RoboGame 2026 robot software

ROS 2 workspace for the one-month two-person sprint. The repository is split into
hardware-independent logic (`robogame_core`) and thin ROS 2 nodes so protocol,
navigation, and mission behavior can be tested without a robot.

See [docs/GETTING_STARTED.md](docs/GETTING_STARTED.md) for Ubuntu setup and the
first-week bring-up procedure.

## 算法、电控、机械三方协作总框架

整车不是“算法写完后交给电控跑”，也不是“机械做好后让算法自己猜接口”。三方需要围绕同一条可验证的数据链协作：

```text
视觉：相机画面 → 方块颜色、距离和左右偏差
                         |
任务算法：决定去哪里、抓哪块、放到哪一层
                         |
运动/抓放协调：生成底盘速度和机构请求
                         |
                         v
robot_bridge：ROS2消息、服务 ↔ 串口帧
                         |
                         v
电控MCU：底盘执行、传感器采集、急停和失联保护
                         |
                         v
机械机构：夹爪、升降、限位和抓取结果传感器
                         |
                         v
状态/里程计/IMU/动作结果返回算法，形成闭环
```

这里的“闭环”是指：算法发出命令后，不能只假定动作成功；电控和机械必须返回实际测量或完成证据，算法再根据结果继续、重试或停车。

### 算法侧负责什么

算法侧负责“决定”和“协调”：

- 从相机图像识别橙色、紫色方块，输出距离和左右偏差；
- 根据轮式里程计和IMU估计小车位置；
- 根据目标位置计算 `vx、vy、wz`；
- 决定任务顺序、路点、抓取颜色和放置层数；
- 在允许误差内对准方块，再请求夹爪和升降动作；
- 检查状态是否新鲜，通信异常、急停或机构故障时停止当前动作；
- 记录失败原因，并决定安全重试还是终止任务。

算法侧不负责替代硬件安全。Ubuntu死机、ROS2停止或串口断开时，MCU仍必须独立停车。

算法侧交付给电控/机械的主要内容：

- 速度命令的消息和单位；
- 机构服务请求及超时时间；
- ROS2话题、消息、服务定义；
- 串口外层帧、CRC和消息类型分配；
- 对状态、完成反馈、时间戳和错误码的需求；
- 分级联调命令、验收标准和日志。

### 电控侧负责什么

电控侧负责“实时执行”和“硬安全”：

- 接收 `vx、vy、wz`，完成麦轮运动解算或执行双方确认的轮速命令；
- 对速度、加速度、电流、电压和驱动状态进行硬件限幅；
- 采集真实编码器、IMU、急停、实体启动和机构传感器；
- 按冻结的单位、正方向、频率和时间戳向上位机回传数据；
- 连续150 ms没有合法速度命令时独立将底盘速度归零；
- 硬件急停直接禁止执行器，不等待上位机响应；
- 拒绝NaN、无穷大、超限值、错误长度和CRC失败帧；
- 重连后保持停车，不恢复断线前的旧命令；
- 为每条机构命令返回最终成功、失败或超时结果。

电控侧需要向算法明确提供：

- 四轮编号、轮径、减速比、编码器分辨率和正方向；
- `vx、vy、wz`的单位、正方向、最大值和死区；
- IMU安装方向、单位、频率和上电校准方式；
- 心跳、重连、看门狗和失联停车行为；
- MCU状态、里程计、IMU和机构命令的逐字节载荷表；
- 可由程序判断的错误码及恢复条件。

### 机械侧负责什么

机械侧负责“机构能否安全完成动作”和“怎样证明完成”：

- 给出夹爪张开、闭合的机械极限和正常动作时间；
- 说明怎样区分“夹爪闭合”和“确实抓到方块”；
- 选择抓取证据：限位、电流、编码器位置或独立传感器；
- 给出升降零点、有效行程、上下限位和三层目标高度；
- 明确 `height_m`对应夹爪、方块底面还是滑块的哪个基准点；
- 说明夹爪、升降和底盘是否允许同时动作；
- 说明堵转、过流、未抓到、掉块、断电和急停后的机械行为；
- 配合制定动作超时、故障码和安全恢复步骤。

机械侧不能只告诉算法“电机转了”。算法需要的是“机构是否达到目标，以及依据是什么”。

详细字段、机构判据和三方确认表见[算法给电控与机械的接口说明](docs/算法给电控与机械的接口说明.md)。

## 三方关键接口摘要

本节只作为索引，具体字段以接口定义和专题文档为准。

### ROS2侧

| 方向 | 接口 | 含义 |
|---|---|---|
| 算法 → 桥接/电控 | `/cmd_vel` | 底盘 `vx、vy、wz` |
| 桥接/电控 → 算法 | `/wheel_odom` | 真实轮式里程计 |
| 桥接/电控 → 算法 | `/imu/data` | IMU测量 |
| 桥接/电控/机械 → 算法 | `/robot/status` | 通信、急停、实体启动、夹爪、方块和机构故障状态 |
| 视觉 → 抓放协调 | `/cubes` | 方块颜色、置信度、距离、横向偏差和角度 |
| 算法 → 机械 | `/gripper/grab` | 请求抓取并等待最终结果 |
| 算法 → 机械 | `/gripper/release` | 请求释放并等待最终结果 |
| 算法 → 机械 | `/lift/set_height` | 请求升降到指定物理高度 |
| 算法 → 桥接/电控 | `/chassis/stop` | 明确停车请求 |

共用消息和服务定义位于 [robogame_interfaces](ros2_ws/src/robogame_interfaces/README.md)。

### 串口侧

串口外层帧已经定义为：

```text
AA 55 | version | type | sequence | payload_length | payload | crc16
```

当前 `0x01`速度载荷已经实现；机构命令、状态、真实里程计和IMU的载荷仍需电控、机械和算法共同冻结，禁止单方猜测字段。详见[MCU协议](docs/MCU_PROTOCOL.md)。

## 推荐联调路线

三方联调应从低风险、可观察的小步骤开始：

1. **软件模拟**：不接真实硬件，先证明消息、任务和错误处理能够运行。
2. **断电通信**：只核对串口帧头、长度、序号、CRC和日志，不驱动电机。
3. **架空底盘**：用很小速度分别测试正反 `vx、vy、wz`和四轮方向。
4. **硬安全**：验证150 ms失联停车、急停、看门狗、上电默认停车和重连不恢复旧命令。
5. **传感器**：手动推动和旋转小车，核对编码器、里程计、IMU单位、方向、频率和时间戳。
6. **机构空载**：分别测试夹爪、升降、限位、回零和动作结果，不运行底盘。
7. **机构带载**：使用正式方块测试抓到、没抓到、掉块、堵转和超时。
8. **单模块闭环**：分别验收视觉、定位、到点控制和抓放。
9. **低速整车闭环**：最后才串联寻找、靠近、抓取、搬运、升降和放置。

前一步未通过，不进入下一步。详细检查项见[集成检查清单](docs/INTEGRATION_CHECKLIST.md)。

## 当前完成度与外部依赖

当前仓库已经具备：

- 九个ROS2功能包和共用消息/服务；
- 可脱离硬件运行的核心算法和自动测试；
- 模拟桥接、模拟视觉和单块任务演示入口；
- 视觉图片/录像处理、HSV/ROI、连续帧确认和结果记录；
- 运动控制限速、超时、越界和状态过期保护；
- 串口外层帧、CRC、速度载荷和流解码；
- 抓放协调流程和软件安全联锁。

仍依赖外部条件完成：

- 正式方块、正式摄像头、光照、ROI和焦距标定；
- MCU真实状态、编码器、IMU和机构载荷字段表；
- 底盘速度方向、轮径、里程计和IMU实车标定；
- 夹爪抓取证据、掉块检测、升降零点和三层高度；
- 急停、失联停车、看门狗和真实机构故障测试；
- 最终整车低速联合闭环。

因此，模拟测试通过不等于真车已经完成。每个真实接口都必须有测量数据、日志和视频作为验收证据。

- [manipulator_client](ros2_ws/src/manipulator_client/README.md)：视觉对准与抓取、升降、释放协调。
- [mission_manager](ros2_ws/src/mission_manager/README.md)：总任务状态机、路点调度、重试和安全停止。
- [robot_bridge](ros2_ws/src/robot_bridge/README.md)：ROS2 与电控串口、底盘和机构服务之间的桥接。
- [robogame_interfaces](ros2_ws/src/robogame_interfaces/README.md)：全系统共用消息和服务合同。
- [robogame_core](ros2_ws/src/robogame_core/README.md)：不依赖硬件的导航、视觉、任务和协议纯逻辑。
- [robogame_bringup](ros2_ws/src/robogame_bringup/README.md)：统一参数和整套系统启动入口。
